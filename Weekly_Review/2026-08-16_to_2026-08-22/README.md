## 2. 今週繰り返し登場した手法・パターン Top5

### ① 「その差は測定できているのか」を先に計算する — 5日中5日

今週の背骨。**改善幅とノイズフロアを比べてから、改善を主張する**という規律が、
3コンペ・15本にわたって別々の形で現れた。

| 出典 | 何をしたか |
|---|---|
| 08-17 Playground | isotonic回帰でOOFを校正し、**AUCの理論天井 0.97006** を10分の計算で推定。以降の探索が物理的に無意味であることを先に示す |
| 08-18 Playground | `notifications_per_day` は単変量AUC 0.492（信号ゼロ）なのに、**残差の折半相関が 0.72**。ノイズと本物のシグナルを分離する実験設計 |
| 08-19 Playground | **Hanley-McNeil (1982)** の公式で公開LB（59,260行）の標準誤差を算出。上位10チームの隣接スコア差より大きい＝**上位陣は統計的に同着** |
| 08-19 Playground | 「弱いベースライン効果」— 同じTEが弱いLGBMでは大きく効き、強いLGBMではほぼ効かない。しかも**ベースラインの強さ自体が +0.0046** で、どの特徴量エンジニアリングより大きい |
| 08-20 Playground | **疑似公開LBシミュレーション**。OOFから実LBと同じ59,260行を層化抽出して「偽のLB」を作り、選択に使わなかった行で評価。10回反復で勝者の呪いを実演 |
| 08-20 RSNA | **採用ゲート**。新しいメタ層はブートストラップ280回の改善正割合と fold一貫性を通過して初めて重みを得る |
| 08-18 RSNA | **no-regressionゲート**。新アームでターゲット別スコアが悪化したら採用せず、親の提出をバイト単位で保持 |
| 08-19 Biohub | `run_stats.csv` を出したことで、**DeepCenterゲートがゼロ件しかチェックしていなかった**（全候補が構造上素通り）ことを発見し、その機構を削除 |

**なぜ今週これほど効いたのか**: S6E8の公開LB上位5本が **0.00004 の幅に収まっている**。
AUC 0.971付近では5桁目の差は数十ペアの順序が入れ替わっただけで生じる。
つまり **改善幅が測定誤差を下回る領域に、コンペ全体が入った**。
この領域では「+0.00002を積む」より「測定器を固定する」（08-20の決定論的タイブレーク付き厳密ランク化）
ほうが先に必要になる。Biohubの`run_stats.csv`の例は、**統計を出さなければ効いていない機構を
効いていると信じ続けていた**という、同じ話の別バージョン。

### ② 順位（rank）空間で合成する — 5日中5日

3コンペすべての指標が ROC-AUC / マクロ平均AUC、つまり**順位しか見ない**。
今週の15本は例外なく、この性質を設計に翻訳していた。

- 08-17 Playground: **rank-gauss変換**（順位→正規分位点）でメンバーのスケール差を吸収
- 08-17 RSNA: `write_submission` で**列ごとに独立に順位化**（指標上ノーコストでアーム間スケールを揃える）
- 08-18 Playground: ブレンドを `rankdata(v)/len(v)` で正規化してから実行
- 08-19 RSNA: `_rad_rank_columns()` で**ラベル列ごとに**順位化してから35チェックポイントを合成
- 08-20 Playground: **決定論的タイブレーク付き厳密ランク化**（`strict_rank` + `np.lexsort`）。同点の並べ方で5桁目が動くため
- 08-20 RSNA: `v12_weight` は**12次元ベクトル**。マクロ平均AUCがラベルごとに独立なら、混ぜ方もラベルごとに独立に
- 08-21 Playground / RSNA: `rank(pct=True)` で揃えてから混ぜる

**効く理由**: 確率平均だと、予測の分散が大きいモデルが実質的に大きな票を持ってしまう（08-19）。
逆に、**確率のキャリブレーションを合わせる努力は指標上まったく無駄**（08-17）。
順位に変換した瞬間、この2つの問題が同時に消える。
ただし08-17が指摘した境界条件は重要 — **同じ手法を log-loss や Brier score のコンペに
持ち込むと逆効果**になる。順位化が無料なのは、指標が順位しか見ないときだけ。

### ③ 多様性の源を「シード違い」ではなく「見ている世界の違い」に求める — 5日中4日

今週最も再利用価値が高いパターン。「同じモデルのシードを増やす」より
**「間違え方の違うモデルを1本足す」**ほうが利得が大きい、という主張が、4つの別々の軸で現れた。

| 多様性の軸 | 出典 |
|---|---|
| **特徴量をあえて外す** | 08-17 Playground: 177メンバーのスタックで、メタモデルが最大の重みを与えたのは**target encodingを外した**XGB / LGBM / CatBoost（単体AUCは低い） |
| **事前学習ドメイン** | 08-19・08-20 RSNA: DINOv2/v3（自然画像・自己教師あり）と RadImageNet ResNet-50（医用画像・教師あり）を併用 |
| **前処理** | 08-20 Biohub: 3つの3D U-Netのうち2つは tophat 変換あり、1つはなし |
| **アルゴリズムの癖** | 08-21 Playground: CatBoostは順序付きターゲット統計を**内部で**持つので、外部の`TargetEncoder`と違う癖の予測を出す |
| **シード（＝弱い軸）** | 08-17 Biohub: 2 seedのロジット混合で0.912。ただし**これは今週唯一の「純粋なシード多様性」**で、他はすべて構造的な違いを狙っている |

**08-17の「Diversity Beats Strength」が最も鋭い**: 全員が使っている特徴量をあえて外すことが、
独立な視点を作る。ここには理論的裏付けもあり、日次レビューが引いた
[Ensembling Tabular Foundation Models（arXiv 2605.18696）](https://arxiv.org/abs/2605.18696) は
6つの表形式基盤モデルの平均ペアワイズ**Q統計量が0.961**と1に近く、
どんな凸結合を取っても上限が決まる「**多様性の天井**」があると報告している。
08-17の実測「AUC天井 0.97006」は、まさにこの天井をこのデータで数値化したもの。

一方で08-19が正直に書いているとおり、エンコーダ共有＋ヘッド差し替えは
**多様性がヘッドの違いからしか来ない**。原著者自身が「5個の追加チェックポイントではなく
2つ目の予測ビューを足しただけ」と書いている。多様性は**足した数ではなく相関で測るべき**。

### ④ 「増やす仕組み」と「却下する仕組み」を別々に持つ — Biohub 5日中4日

Biohub枠に固有だが、思想としては最も転用しやすいパターン。
後処理でFNを減らすとFPが必ず増えるため、**増やす側だけ強化しても指標（F1系）は伸びない**。
そこで今週のnotebookは揃って、修復機構とブレーキを分離していた。

- 08-17: DeepCenterUNet3D を「補間で作った合成ノードのうち判定が微妙なものだけ」に問い合わせる。
  独立な検出器を**全体の判断権者にせず、1つの修復クラスの精度役に留める**
- 08-18: エッジポリシーを**エッジを消すためだけ**に使い、追加には使わない。しかも閾値 τ=0.35 を
  OOFのF1最適閾値より**わざと低く**設定（Recallを守りながら明らかな誤リンクだけ削る）
- 08-19: 閾値0.970＋最小トラック長6でPrecisionを守り、ギャップ復元（max_gap=2）でRecallを取り戻す
  という**対称なペア**。片側だけではF1は伸びない
- 08-21: **DeepCenter拒否権** — 復元するたびに独立に学習した中心検出U-Netに問い合わせ、低ければ却下。
  さらに `GAP_REFINE_MAX_SHIFT_UM` 超過なら補正自体を却下、`SAFE_DIV_GLOBAL_FRAC_CAP` で
  追加分裂の総量に上限で蓋

08-17の「出現の重み 0.0 / 消失の重み 1.5」も同じ発想の別形。
**「視野に入るのは自然、途中で消えるのは不自然」という事前知識を、そのまま最適化のコストに変換**している。

### ⑤ ラベル／所見ごとに設計を分ける — RSNA 5日中5日

マクロ平均AUC（12ラベルのAUCを個別計算して単純平均）は、**12ラベルを対等に扱う**。
稀なラベル（骨折・骨挫傷）を捨てる戦略が封じられるので、設計もラベル単位になる。
今週のRSNA枠5本すべてが、この構造に沿っていた。

- 08-17: 12所見それぞれに学習可能クエリを1本持たせ、study内の全シリーズへcross-attention
- 08-18: ターゲットのグループ化（靭帯/半月板/OA/炎症/骨）で、陽性の少ないラベルが同グループから表現を借りる。
  **Mean-Maxデュアルプーリング**（局所所見はmax、びまん性所見はmean）を両方計算して連結しヘッドに選ばせる
- 08-19: `TTA_TARGET_POOL` — `Fracture`/`Contusion`は`max`、`ACL`/`MCL`は`top2`、`Synovitis`は`mean`。
  さらに `_RAD_EXCLUDE` で2ラベルだけRadImageNetを混ぜない（**アンサンブルは全ラベル一律に効くとは限らない**）
- 08-20: `LabelAttentionPool` — 40枚中2枚にしか写らない骨折の信号は単純平均では消えるので、
  **ラベルごとに見るべきスライスを学習**する
- 08-21: ターゲット別TTAプーリング＋ターゲット別融合ゲートα（ベーカー嚢腫と骨折だけ α=0.0）

**核心は「医学的な所見の性質を、プーリング関数の選択に翻訳している」（08-19）**という一点。
骨折は1枚のスライスにしか写らない局所所見なので平均すると信号が薄まり、
滑膜炎のようなびまん性の所見は平均のほうが安定する。
指標の構造 → 設計単位、ドメイン知識 → 集約関数、という2本の翻訳が同時に走っている。

### （番外）静かな失敗を機械的に検出する — 5日中5日

Top5に入れなかったが、今週**全15本のうち10本以上**に現れた最頻出パターンなので記録しておく。

- **指紋照合（fingerprint）**: 固定シードのランダム入力を通した出力を照合（許容誤差0.002）。
  `load_state_dict(strict=False)` が黙って一部だけ読み込む事故を決定的に検出（08-17 / 08-18 / 08-19 / 08-21）
- **fail-closed**: 回復可能な例外 → 全ラベル0.5の提出を残して生存。`LabelSourceError`（前提の崩壊）→ 再送出して停止。
  **握り潰してよい失敗と、気づくべき失敗の区別**（08-17 / 08-18 / 08-21）
- **収束のアサーション**: `assert max(n_iter_) < max_iter`。収束していないロジスティック回帰は
  **真の値より高いスコアを静かに出す**（08-17）
- **予測配列のMD5重複検出**: 実際に2組の完全重複を発見。放置するとそのモデルの重みが黙って2倍になる（08-17）
- **提出IDの明記**: 「記憶では上がった」ではなく `submission_ref: 55584395` と書く（08-20）
- **穴の実例**: 08-21のモンキーパッチ `_s.replace(_old, _new)` は、上流の文字列が1文字変わると**静かに失敗**する。
  `if _old not in _s: raise` を1行足すだけで「TTAが効いていないまま高スコアだと思い込む」事故を防げる

## 3. 今週の珍しい・特徴的な手法

### 疑似公開リーダーボード・シミュレーション（08-20 Playground）

今週で最も移植価値が高い。**OOFさえあれば、どのコンペでも今日から実行できる。**

1. OOFから、実際の公開LBと同じ **59,260行を層化抽出**して「偽の公開LB」を作る
2. そこで最良のブレンド重みを選ぶ
3. **選択に使わなかった行**で評価する
4. これを10回繰り返す

結果は「選んだ場所では上がるが、選ばなかった場所では下がる」——**勝者の呪い**の実演。
さらに強い証拠として、**符号の逆転**を使っている。正直なOOFは「生徒モデルを+12%足せ」と言い、
公開LBは「-8%引け」と言う。値のズレではなく**最適な方向が反転する**ことが、
公開行に固有のノイズを拾っている証拠になる。

裏づけとして、完了済みSeason 6の7エピソードで公開top10がprivate top10に何チーム残ったかを集計すると、
**3回は生存者ゼロ**、S6E7では**公開1位がprivate 440位**だった。

### 連続値の「文字列化（Stringify）」トリック（08-21 Playground）

`sleep_hours` などの連続値を `.astype(str)` でカテゴリに変換してからターゲットエンコーディングをかける。
Playgroundのデータは小さな実データ（約7,500行）から生成した合成データなので**値が格子状に並ぶ**。
木モデルは大小関係の分割しか作れないため格子構造を効率よく表現できないが、
各格子点を「その値のときの陽性率」に変えてしまえば **生成ルールの逆算**になる。

「合成データである」というメタ知識が、そのまま特徴量エンジニアリングの方針になった例。
08-18の「`daily_screen_time ≥ social + gaming + work` が859,029行の**100.00000%**で成立」という発見も同系統で、
そこから作った残差特徴量（説明のつかないスクリーンタイム）は単独AUC 0.765 と、
`gaming_hours`（0.62）より遥かに強かった。**物理的な制約から作る特徴量は、単なる交互作用より強い。**

### 構造的な限界の発見 — safe divisions（08-20 Biohub）

ハンガリー法は必ず1対1の割当なので、**分裂の2人目の娘は原理的に絶対リンクされない**。
実測で分裂 TP/FP/FN = 0/0/14、つまり1個も検出できていなかった。
そこで姉妹細胞の**相互最近傍**性と、**分裂後に離れていく**こと
（`d(succ(c1),succ(q)) - d(c1,q) ≥ 2.25µm`）で救済する。
未来の情報を使って「たまたま近い2細胞」と「今まさに分かれた姉妹」を区別する発想。

ここでの教訓は手法そのものより、**スコアが伸びない原因がモデルではなくアルゴリズムの構造にある**
ことがある、という点。モデルをもう1本足す前に、
**今のパイプラインが構造的に表現できないものは何か**を問う価値がある。

### バグを追うことを選んだ日（08-21 Playground）

2モデルのスタッキングをしているのに、**単体のLGBM（0.96965）に0.005負けている**という異常から、
メタ特徴量の列名不一致（`lgbm_oof_rank` vs `lgbm_test_rank`）に辿り着いた回。
`assert list(meta_X_train.columns) == list(meta_X_test.columns)` の1行で検出できる。
**スコアが期待より低いときは、まず実装を疑う**——高スコアnotebookを眺めるだけでは得られない経験。

## 5. 今週の論文消化との接続

[Paper_Digest/2026-08-19](../../Paper_Digest/2026-08-19/) — **MOSAIC: A Multilingual, Taxonomy-Agnostic,

この回は**日次レビューの指摘から論文選定が駆動された**、今週で最も良いループになっている。

- 08-17の日次レビューが「このコンペは『ラベルはレポート由来』なので、**レポート解析の質が上流のボトルネック**」
  「ラベルの質は全アームの上限を決める」「否定表現（negation）の扱いが未検証」と指摘
- 08-18の日次レビューで、上位notebookが**9言語分の正規表現辞書＋近接マッチング（窓55文字）**という

MOSAICの要点は、MedGemma-4B（4bit量子化で**RTX 4090一枚**で完結）を使い、
分類したい所見の一覧を**プロンプト側で差し替えるだけ**でタスクが変わる taxonomy-agnostic な設計。
`+`（陽性）/`−`（陰性）/`~`（不確実）の3値を区別し、**(+)F1 と (−)F1 を別々に報告**する。
つまり **否定表現の扱いが評価指標に明示的に組み込まれている** — 08-17が指摘した穴に、
評価の側から答えている。多言語の積み上げが干渉せず改善したこと、
データ拡張併用なら**新しい言語・ラベル体系への適応に必要なアノテーションは80件程度**という報告も、
16施設・十数言語のRSNA Kneeにそのまま効く。

**未接続の宿題**: 08-20の日次レビューで、RSNA上位帯（0.921）が採用していない最大の要素は
**放射線レポート由来の弱教師あり学習**（0.906のnotebook系統）だと特定されている。
画像だけの系統が0.92で頭打ちになっている以上、**モダリティを増やす**のは残された数少ない大きな一手。
MOSAICはその実装方針そのものなのに、**まだKaggle側で試していない**。ここが最大の未回収。

## 6. 一言まとめ

今週は「複雑さを足すこと」より「**複雑さを足す価値があるかを先に判定すること**」に
時間を使った週だった（08-17のまとめの表現がそのまま週全体に当てはまる）。

3コンペとも上位が密集帯に入っている——S6E8は上位5本が0.00004幅、RSNAは0.917〜0.921、
Biohubは正攻法組が0.90〜0.92。この状況で伸びるのは、
**測定器を固定する → 構造的な限界を特定する → その限界を外す一手を打つ**という順序だと思う。
今週は1つ目と2つ目が揃った。

### 来週意識したいテーマ（優先順）

1. **「構造的に表現できないものは何か」を各コンペで1つ書き出す**。
   08-20のsafe divisions（ハンガリー法が1対1である限り分裂の2人目は原理的に検出不能）が最良の例。
   モデルを1本足す前に問うべき質問。
2. **Hanley-McNeil計算をRSNAにも適用する**。08-19の日次レビューが「最も費用対効果の高い次の一手」として
   挙げたまま**まだ実施していない**。0.917と0.921の差が測定できているのかを先に決める。
3. **レポート由来の弱教師をRSNAの第4の系統として試す**。MOSAICを読んだのに実践に落としていない。
   画像のみの3系統はすべて事前学習ドメインの違いだが、**テキストは別モダリティ**なので
   多様性の源としてはるかに強い（今週のパターン③の最も大きな適用先）。
4. **多様性を「足した数」ではなく「OOF予測の相関行列」で測る習慣**。
   08-19が正直に認めた「エンコーダ共有の代償」も、08-17のMD5重複検出も、
   相関を出せば同じ画面で見える。
5. **S6E8は「21本目のブレンド」を打ち切る**。今週すでに3日その判断をしている。
   残りの学びは中間帯（ラベルがコイン投げになる約14%）に絞ったモデリングくらい。
