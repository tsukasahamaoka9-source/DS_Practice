## 1. Biohub - Cell Tracking During Development（固定枠）

**Biohub Cell Tracking: Blend Preprocessings**

- **原著者**: PILKWANG KIM
- **リンク**: https://www.kaggle.com/code/pilkwang/biohub-cell-tracking-blend-preprocessings
- **スコア**: Public 0.900 / Best 0.900 (V36)・155 votes（Gold）
- **ローカル**: `biohub_biohub-cell-tracking-blend-preprocessings.ipynb`

### 学べる主要テクニック

- **環境変数によるハイパーパラメータの外出し**: 追跡処理の本体（外部リポジトリ）は一切書き換えず、`BIOHUB_*` 環境変数だけで挙動を切り替える。「同じコード・違う設定」の実験を大量に回せる構造。
- **1軸キャリブレーション（one-axis probe）**: 基準設定（0.9700アンカー）から**1パラメータだけ**動かす実験設計。複数を同時に動かすと、スコアが動いても原因が特定できない。
- **条件付きギャップ補修 + 独立モデルの拒否権**: 距離 $d$ が 8μm 未満なら無条件採用、8〜12μm の**微妙な帯だけ** DeepCenter の確率 ≥0.20 を要求、12μm 超は却下。「全体を平均する」のではなく「**不確実な領域だけ第2の意見を使う**」タイプのアンサンブル。
- **物理単位での距離計算**: ボクセル間隔が z=1.625μm / xy=0.40625μm と4倍違うため、ボクセル数で距離を測ると縦方向を過大評価する。μm に直してから距離を取る。
- **モンキーパッチによる検出TTAの拡張**: 推論スクリプトを文字列置換で書き換え、flip 3種に 90°/270° 回転を追加。細胞は等方的なので回転TTAが物理的に妥当。
- **オフライン依存解決**: Code Competition はネット遮断されるため、wheel を添付データセットから入れる3段構え（既存 → wheel → 明示許可時のみネット）。
- **ハンガリアン法（`linear_sum_assignment`）**: フレーム間対応を割当問題として全体最適に解く。貪欲法と違い密集細胞での取り違えが起きにくい。

### 評価指標の要約

Cell Tracking Challenge 系の**編集距離ベースの追跡指標**（DET/TRA系）。正解の系統グラフに変換するために必要なノード・エッジの編集コストを正規化したもので、生物学者が知りたい「細胞の家系図が正しいか」を直接評価する。**偽エッジの追加コストと真エッジの欠落コストが非対称**なので、「自信があるときだけ繋ぐ」保守的な後処理が有利になる — このnotebookの閾値設計はすべてそこから来ている。

**関連文献**:
- **HOCT (Higher-Order Cell Tracking Transformer, arXiv 2607.11754, 2026年7月)** — まさにこの課題の急所を突いている。候補グラフの構造的障害を2つ指摘: ①**細胞分裂がノード埋め込み空間で複数の系統パスを絡ませる**、②**同じノードを共有するエッジのラベル一致率がほぼランダム**なので、候補グラフのトポロジーはGNNが集約すべき情報を持っていない。解決として**エッジ中心（edge-centric）アーキテクチャ**を提案し、候補リンク同士が3D幾何事前分布のもとで互いにattendする。深い事前学習画像エンコーダなしで Cell Tracking Challenge のSOTAを達成。
- **ARGUS (arXiv 2607.08297)**, **Segment Anything for Cell Tracking (arXiv 2509.09943)** — 教師なし／基盤モデル系のアプローチ。

**改善提案**:

1. **エッジ中心の関連付けに置き換える**。本notebookの Node Transformer は「ノード埋め込みを見てエッジをスコアリング」する方式だが、HOCTの指摘通り、分裂が絡むとノード埋め込みは複数系統を混ぜてしまう。**エッジ同士をattendさせる**構成に変えれば、「このエッジを採るならあのエッジは採れない」という排他関係を学習で表現でき、ILPに渡す前の候補品質が上がる。
2. **拒否権の帯を1つでなく複数持たせる**。現在 DeepCenter が口を挟むのは「1フレームギャップの 8〜12μm 帯」だけ。同じ論理は**分裂判定**にも適用できるはずで、`BIOHUB_SAFE_DIV_MAX_UM=4.66` 付近の境界例に対して独立モデルの確認を入れれば、保守的な閾値をもう少し緩められる可能性がある。
3. **DeepCenter 閾値 0.20 の感度分析**。この値だけがハードコードで、1軸プローブの対象になっていない。0.10 / 0.15 / 0.25 / 0.30 を振って公開スコアの応答を見るべき。応答が平坦なら「この機構自体があまり効いていない」証拠になり、鋭ければ過剰適合の疑いが出る。
4. **検出側に投資を移す**。0.965+ 帯との差を埋めるなら、後処理の閾値をこれ以上いじるより、`biohub ct mix divaug` が使っている**分裂特化の学習時拡張**を取り込む方が期待値が高い。
5. **モンキーパッチの失敗を検出可能にする**。現在の実装は `_old` がマッチしなければ静かに何もしない。**置換件数を assert する**だけで、上流リポジトリの更新でTTAが黙って無効化される事故を防げる（皮肉にも、この notebook 全体の思想＝「静かに失敗させない」に反している唯一の箇所）。

## 2. Playground Series S6E8 - Predicting Smartphone Addiction

**S6E8 Addiction Blend — LB 0.97117**

- **原著者**: thisray
- **リンク**: https://www.kaggle.com/code/thisray/s6e8-addiction-blend-lb-0-97117
- **スコア**: Public 0.97117（公開notebookの最高帯）
- **ローカル**: `playground_s6e8-addiction-blend-lb-0-97117.ipynb`

> **選定の経緯（メモ）**: 当初は最多得票の「S6E8 Addiction LB 0.97113」(79票) を取得したが、中身が**提出ファイルの読み込みと保存だけ**で学習コードが非公開だったため、学習価値がないと判断して差し替えた。高スコア公開notebookには「結果だけ共有」型が混ざるので、中身を確認してから採用する必要がある。

### 学べる主要テクニック

- **rank blend（順位ブレンド）の実装**: 全予測を `rank(pct=True)` で 0〜1 の一様分布に変換してから重み付き和。**AUCは順位しか読まない**ので情報損失ゼロで、かつ「自信過剰なモデルが支配する」問題を消せる。
- **異種フォーマットの統合パターン**: `.npy` / `.parquet` / `.csv` が混在する85本の配列を、`作者__配列名` という命名規約 + `load_test()` 1関数で吸収。`WEIGHTS` に1行足すだけでモデルを追加できる**設定とロジックの分離**。
- **`sample_submission` を基準順序にする**: `set_index("id").loc[sub_ids]` で全配列を明示的に整列。「たぶん同じ順」で進めると、**形式は正しくエラーも出ない**まま完全に無意味な提出ができあがる。
- **`float64` で累積する**: 正負が打ち消し合う85項の加算では `float32` だと桁落ちする。
- **最後にもう一度 rank 化する**: AUCでは無害（単調変換）で、出力が0〜1に収まる安全策。ただし**RMSE/LogLossのコンペで同じことをすると壊滅する**。

### 評価指標の要約

**ROC-AUC**（順位のみを読む、閾値・クラス比率に不変）。この性質から後処理の形が一意に決まる — キャリブレーション不要、モデル合成は生確率平均ではなく**rank平均**が正しい。

### 改善点の考察

**他notebookとの比較**（S6E8 のスコア上位を確認）:

| notebook | スコア | 性質 |
|---|---|---|
| S6E8 Addiction Blend（本notebook） | 0.97117 | 85配列のリッジ重み rank blend |
| S6E8: Elite Rank Average Ensemble | 0.97117 | 等重み寄りの rank average |
| **Why Every S6E8 Notebook Above 0.97110 Overfits** | 0.97115 | **上記を名指しで批判するnotebook** |
| S6E8 Addiction LB 0.97113 | 0.97113 | 提出ファイル共有のみ |
| 単体モデル（CatBoost / LGBM / HGB） | 0.9676〜0.9695 | ベースライン |

ここが今日いちばん面白い点です。本notebookの 0.97117 は、**本ルーティンが 2026-08-20 に扱った「Why Every S6E8 Notebook Above 0.97110 Overfits」の批判の射程にちょうど入っている**。しかもその批判は根拠が具体的で、`WEIGHTS` を見れば裏付けが取れます — `szymon__latr1_xgb: +1.303` と `szymon__lat_lgbm: -1.014` のように、**大きさが1を超えて正負で打ち消し合う係数**が並んでいる。これは多重共線性下のリッジ回帰の典型的な振る舞いで、実質「2モデルの差分」を特徴量に使っている状態。OOFのノイズに乗っている可能性が高い。

**関連文献・コミュニティ知見**:
- Kaggle の上位writeup（[PS S5E12 1st place: Hill Climbing + Ridge](https://www.kaggle.com/competitions/playground-series-s5e12/writeups/1st-place-solution-hill-climbing-ridge-ensembl)、[PS S4E9 3rd place: Gather, Ridge, Repeat](https://www.kaggle.com/competitions/playground-series-s4e9/writeups/optimistix-3rd-place-solution-an-open-secret-gathe)）では、リッジブレンドは**hill climbing との併用**が定石。hill climbing は係数を非負・逐次追加に制限するため、打ち消し合う巨大係数が構造的に出ない。
- 同writeup群では **OOF と Public LB の乖離幅を監視する**運用が紹介されている（健全な gap ≈ 0.00185、これを 0.00190 超に広げる実験は即破棄）。CVスコアだけを見て採否を決めない、という規律。
- [PS S6E2 4th place: "Less is More"](https://www.kaggle.com/competitions/playground-series-s6e2/writeups/4th-place-solution) は逆方向の主張で、**stump（深さ1の木）+ rank ensemble** という極端に単純な構成で4位。相関の高いOOFを大量に混ぜるほど過剰適合しやすい、という経験則の裏返し。

**改善提案**:

1. **非負制約付き（NNLS）または hill climbing に置き換える**。係数を非負に制限すれば、打ち消し合いによる見せかけの利得が構造的に消える。OOFスコアは下がるが、private での順位保持は改善する可能性が高い。
2. **重みの安定性を測る**。OOFを複数のシード／分割で切り直し、**各係数の分散**を見る。`latr1_xgb` のように大きく振れる係数は、その配列を落とすか正則化を強めるべき候補。
3. **相関で刈り込んでから重みを付ける**。85本のうち相関 0.99 超のペアは片方落としても情報は失われない。**まず配列数を減らしてから**リッジを当てれば、多重共線性そのものが軽くなる。
4. **OOF−LB gap を採否基準にする**。上のwriteup群の運用をそのまま持ち込む。OOFが上がったのにgapが広がる実験は捨てる。
5. **単体モデル（0.968）との差 0.003 の内訳を分解する**。85本のうち上位10本だけで何点取れるか、20本なら、50本なら — という曲線を描けば、「どこから先がノイズを拾っているだけか」が可視化できる。曲線が平坦になった後の配列は、**過剰適合のリスクだけ増やして期待利得はゼロ**。

## 3. RSNA Knee Abnormality Detection（開催中・残り2ヶ月）

**RSNA Knee baseline v1**

- **原著者**: PILKWANG KIM
- **リンク**: https://www.kaggle.com/code/pilkwang/rsna-knee-baseline-v1
- **スコア**: Public 0.891 / Best 0.891 (V15)・**396 votes（Gold・本コンペ最多得票、2位の235を大きく引き離す）**
- **ローカル**: `competition_rsna-knee-baseline-v1.ipynb`

> **選定理由**: 本ルーティンではRSNA Kneeを12本ほど扱ってきたが、そのほぼ全てが**このbaseline v1の派生**だった（`frontier v46/v48`、`dinosaur v2/v3`、`baseline-v1-fracture-tta-pool-probe` など）。土台そのものを一度も読んでいなかったので、今日そこを埋める。スコアは最上位(0.922)に劣るが、**「なぜそうしたか」が全編に書かれている**極めて教育的なnotebook。

### 学べる主要テクニック

- **指標から設計を演繹する**: 「12ラベル平均AUC」という指標だけから3つの設計判断が決まる — ①順位しか見ない→rank合成、②12ラベル等価→**希少所見にこそ手をかける**（1ラベル放置で $(M-0.5)/12 \approx 0.029$ の損失）、③有病率ドリフトには強いが閾値には弱い。
- **多言語ルールベースのラベル抽出（弱教師）**: 12ラベル付きstudyはごく一部だが、**全studyに9言語のレポートがある**。節単位で肯定/否定/曖昧を判定し、**信頼度をサンプル重みにする**。
- **言語判定をしない設計**: 9言語のキューを全部まとめて当てる。「証拠を読む前に賭けをしない」。`'la '` は仏語にも西語にも出るので安易な判定は破綻する。
- **否定処理を主役に据える**: 読影レポートは「調べたが異常なし」を列挙する文書。所見名の出現＝陽性という素朴実装は**ほとんどのケースで真逆のラベル**を作る。スコープは文字数ウィンドウでなく**節全体**（トルコ語は否定辞が文末、英語は文頭）。
- **DICOMヘッダから撮像条件を復元**: 提供された `Fluid_Sensitive` と `Fat_Suppression` は訓練全行で一致＝実質1軸。$T_R/T_E$ から contrast weighting（T1/T2/PD）を、`ScanOptions` 等から脂肪抑制を復元して2軸に戻す。
- **スライス順序を幾何から復元**: ファイル名(SOP UID)順と物理位置の順位相関は **ρ ≈ 0.01（無相関）**。$\hat n = \hat r_x \times \hat r_y$、$k = p\cdot\hat n$ で厳密に並べ直す。
- **Nyquist条件によるリサンプル設計**: 半月板断裂は1〜3mm → 画素ピッチ $\le 0.5$mm が必要。固定ピクセル数リサイズではなく**固定物理範囲 $L=130$mm でクロップ**してから $P$ ピクセルへ。届く前に消えた信号は、どんな容量でも回復できない。
- **左右正規化**: 12所見中5つが内外側依存。冠状/横断はミラー、**矢状断はスライス順序の反転**（幾何的に別処理）。`Laterality` は半数欠損 → 患者座標系の $x$ 符号から復元。
- **所見ごとのマスク付きattention pooling**: 最大6スロットを、12所見それぞれの独立クエリで集約。**ヘッドを意図的に小さく保つ**（ラベルがstudy単位なので、それ以上細かい集約は学習する手がかりがない）。
- **fingerprint による前処理整合性検証**: 重みと前処理が食い違っても**エラーは出ず、走り切り、間違った画像から計算した提出を返す**。シード生成した合成入力への出力を「指紋」として照合する。
- **拡張の「入れない理由」を分ける**: 水平フリップは*除去済みの迷惑変数を再導入するから*入れない。垂直フリップは*そもそも変動しない軸だから*入れない。
- **例外の非対称な扱い**: デコード失敗等は 0.5 ベンチマークにフォールバック（提出できないと0点）、しかし `LabelSourceError` は**握り潰さず止める**（間違ったラベルで学習したランは、完走して提出する価値のある提出を書いてしまう）。
- **レポートハッシュによる分割**: 定型文のレポートはバイト一致するので、ハッシュでstudyを割り当てて重複グループを分断しない。**holdout（導出ラベル、十分なn）が判断し、annotation check（画像ラベル、少数n）は報告のみで判断させない**。

### 評価指標の要約

**12所見のROC-AUCの単純平均** $\frac{1}{12}\sum \mathrm{AUC}_i$。順位のみを読み、12ラベルは等価。したがって希少所見（骨折など）を1つ放置すると平均AUC $M=0.85$ 換算で **0.029** を失い、他の11個をどれだけ磨いても取り返せない。提出は必ず列ごとに rank 化して書き出し、失敗時は全ラベル 0.5 のベンチマークを書く。

### 改善点の考察

**他notebookとの比較**（同コンペのBest Score上位を確認）:

- **[MM-DINOv2 (arXiv 2509.06617)](https://arxiv.org/pdf/2509.06617)** — DINOv2 をマルチモーダル医用画像に適応させる手法。**欠損モダリティの扱い**を明示的に設計している点が、本notebookの「マスク付きsoftmaxで欠損スロットを除く」処理の直接の発展形。
- **[Large-scale Multi-sequence Pretraining for Generalizable MRI Analysis (arXiv 2508.07165)](https://arxiv.org/pdf/2508.07165)** — T1W/T2W/PDW を横断してMRI専用に事前学習。本notebookが §「なぜ凍結せず学習するのか」で述べた「自然画像で学んだ語彙の天井」を、**そもそもMRIで事前学習することで外す**アプローチ。
- **[Clinical utility of foundation models in musculoskeletal MRI (npj Digital Medicine, 2026)](https://www.nature.com/articles/s41746-026-02520-w)** — 筋骨格MRIにおける基盤モデルの臨床的有用性。
- コンペのフレーミングとして「4,407 studyのうち画像由来ラベルは58件のみ、4,349件はレポートあり。**レポート由来ラベルと画像由来正解の一致は約82%**」という数字がある。これは本notebookの弱教師設計の妥当性と、同時にその上限を示している。

**改善提案**:

1. **エンコーダをMRI/医用事前学習に差し替える**。§「なぜ凍結せず学習するのか」の議論を一歩進めると、末尾ブロックだけ動かして自然画像の語彙を医用に寄せるより、**最初から医用で事前学習された語彙**（RadImageNet、arXiv 2508.07165 のマルチシーケンス事前学習）を使う方が天井が高い。実際 DINO-RadImageNet rank ensemble が 0.920 を出している。
2. **希少所見に指標由来の重み付けを入れる**。§1が「希少所見にこそ手をかけるべき」と正しく指摘しているのに、**損失側では信頼度重みしか使っていない**。骨折のように陽性が数十例しかないヘッドは、focal loss や per-label な positive weight で明示的に持ち上げる余地がある。1ラベルを0.5から0.80に引き上げるだけで +0.025 相当。
3. **co-plane attention へ拡張する**。現在のSlotHeadは所見クエリ→スロットの1段attention。Nature Comms の co-plane attention のように**スロット同士を先に相互作用させる**層を1つ挟めば、「矢状断で見えた所見の裏を冠状断で確認する」ような推論が表現できる。ただし §6 の警告（study単位ラベルでは細かい集約を学習する手がかりがない）は依然有効なので、**パラメータを増やすなら holdout で厳密に検証**すること。
4. **レポート抽出器の「沈黙率」を改善に繋げる**。§2 が「語彙が薄い場所は、マッチ率（アノテーション不要で測れる）で分かる」と述べ、ギリシャ語で取りこぼしが集中していることまで特定している。**そこまで分かっているなら辞書を足せる**。レポート由来ラベルと画像由来正解の一致が82%という数字を、言語別に分解すれば投資先が決まる。
5. **メンバーを増やして rank ensemble する**。§6b の「メンバー方式」と fingerprint の仕組みは**すでに複数メンバーを想定して作られている**。解像度・スライス数・エンコーダ違いのメンバーを3〜5個作って rank 平均するだけで、上位帯との差の半分は埋まると見られる。ここは実装コストが最も低い。
6. **効率性トラックを見る**。「RSNA Knee Abnormalities - Efficiency LB」が216票集めているのは、**推論時間あたりのスコア**も評価される枠があるため。本baselineは §5b でメモリ予算を丁寧に管理しており、効率性トラックとの相性が良い。ここは競争が薄い可能性がある。
