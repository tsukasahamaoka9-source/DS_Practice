## 1. Biohub - Cell Tracking：UNet + ILP + エッジポリシーveto

**原著者**: YAROSLAV KHOLMIRZAYEV ・ 130 votes（Gold）・ Apache 2.0
**リンク**: https://www.kaggle.com/code/yaroslavkholmirzayev/biohub-cell-tracking-v4-unet-ilp-reproduction

### 学べる主要テクニック

- **3段構えのパイプライン**: 学習済み検出器＋リンカー（UNet+Transformer）で候補グラフ → ILPで整合的なエッジ集合を選択 → 幾何・ポリシー制約による保守的な修復。
- **ILPで構造制約を「制約式として」書く**: 「後継は高々1つ、分裂なら2つ」を最適化問題の制約に落とし込むことで、確率の閾値処理では必ず出る物理的に不可能な解を構造的に排除する。
- **エッジポリシーの非対称な使い方（veto）**: 学習済みポリシーは**エッジを消すためだけ**に使い、追加には使わない。しかも閾値 τ=0.35 は OOF の F1 最適閾値より**わざと低く**設定。
- **異方性ボクセルの物理単位換算**: `VOXEL_SCALE_UM = (1.625, 0.40625, 0.40625)`。z方向がxyの4倍粗いので、生のボクセル座標で距離を測るとz方向の移動を1/4に過小評価する。初心者が最も踏みやすい罠。
- **ギャップ復元をノード挿入で表現**: 提出形式が「連続フレーム間の直接リンク」しか許さないため、1フレーム飛びを繋ぐには中間ノードを作って2本に割る。

### 評価指標の要約

検出（ノード）とリンク（エッジ）のマッチングに基づく**F1系のトラッキング精度**。ありうるエッジの組み合わせが爆発的に多く極端なクラス不均衡があるため、Accuracyでは「エッジをほとんど張らない」戦略が勝ってしまう。F1はPrecisionとRecallの調和平均なので、**取りこぼしと誤リンクを同時に罰し**、片方が極端に低いと全体が引きずられる。この notebook の「veto閾値をF1最適閾値より低くする」設計は、Recallを守りながら明らかな誤リンクだけ削るという、F1に対して極めて理にかなったチューニング。

### 改善点の考察

**他notebookとの比較**（同コンペのBest Score上位を確認）:

| notebook | スコア | このnotebookが採用していないもの |
|---|---|---|
| biohub ct mix divaug | 0.969 | 分裂イベントに特化したデータ拡張（division augmentation） |
| Biohub Cell Tracking Solution | 0.966 | 大規模なマルチシード/マルチモデルのアンサンブル |
| Dark-AGI Biohub Solution | 0.952 | 複数前処理のブレンド |

このnotebookは0.896で、上位陣とは**0.07という大きな差**がある。ただし上位陣の多くは重いアンサンブルで、こちらは単一モデル＋決定論的な後処理という点で構造が遥かに明快。**伸びしろが素直に残っている**とも言える。

**関連文献**: [Higher-Order Cell Tracking Transformer (HOCT, arXiv 2607.11754, 2026年7月)](https://arxiv.org/html/2607.11754) が、まさにこのnotebookの弱点を突く形になっている。HOCTは**エッジ中心のアーキテクチャで候補リンク同士を3D幾何事前分布の下でattentionさせる**もので、論文中では「appearance probability（出現確率）を可変にすることが一貫して有効」「長いリンクには two-pass tracklet solver が必要で、それがないと**同じ経路上の長さの違う候補エッジがILPの中で競合してしまう**」と報告されている。この notebook は `--ilp-appearance-weight` を固定値で渡しており、まさにこの指摘の対象。また [Cell-TRACTR](https://pmc.ncbi.nlm.nih.gov/articles/PMC12101859/) も、ILPベースのリンクが貪欲法より優れることを実証している。

**改善提案**:

1. **appearance weight を固定値でなく可変にする**。HOCTの知見に従い、局所密度や検出確信度に応じて出現コストを変える。密集領域では出現を強く罰し、疎な領域では緩める、といった適応が素直に効きそう。
2. **two-pass tracklet solver の導入**。まず短く確実なトラックレットを確定させ、次にトラックレット間の接続を解く。長いギャップリンクと短いリンクが同じILPで競合する問題を構造的に回避できる。
3. **veto を「消すだけ」から「重み付け」に拡張する**。現在はτ=0.35で二値的に消しているが、ポリシー確率をILPの目的関数の係数に組み込めば、閾値の恣意性がなくなり最適化が一貫する。ただし「保守的であること」という設計思想は保つ必要がある。
4. **分裂イベント特化の拡張**（0.969のnotebookが採用）。分裂は稀なイベントなので学習データが少ない。合成的に分裂サンプルを増やすのが最も費用対効果が高い可能性。
5. **det-threshold の per-video 適応**。動画ごとに細胞密度も画質も違うので、固定閾値ではなく各動画の検出確率分布から適応的に決めると、Recallの底上げになりそう。

## 2. Playground S6E8：Lookup-Transformer

**原著者**: Tamerlan Omralinov ・ 30 votes ・ Apache 2.0
**リンク**: https://www.kaggle.com/code/tamerlanomralinov/s6e8-lookup-transformer-insights-lb-0-97041

### 選定について（今日は意図的にトップスコアを選ばなかった）

本日の公開LB最上位は [0.97099のnotebook](https://www.kaggle.com/code/daniilkrasnovvv/s6e8-top-1-public-0-97099) だったが、中身は**他人の提出CSV 3本をrank平均しただけの4セル**で、学べる内容がほぼ無かった。こちらは0.97041（差はわずか0.0006）ながら、**データ生成過程そのものを実験で突き止め、そこに合わせてモデルをゼロから設計している**。スコア0.0006より、この思考プロセスのほうが学ぶ価値が遥かに大きいと判断した。

### 学べる主要テクニック

- **split-half reliability による「暗記可能性」の証明**: `notifications_per_day` は単変量AUC 0.492（単調な信号ゼロ）なのに、独立な2つの四半分で計算した**値ごとの残差の相関が0.72**。モデルを噛ませて残差を取ることで構成効果を除去し、2つの独立標本で相関を見ることでノイズと本物のシグナルを分離している。実験設計として非常に美しい。
- **生成制約の発見と対照実験**: `daily_screen_time ≥ social + gaming + work` が859,029行の**100.00000%**で成立、最小ギャップ0.000。しかも**weekendでは成立しないことを対照実験で確認**しているので、主張が強い。差分（説明のつかないスクリーンタイム）は単独AUC 0.765。
- **PLR（Periodic-Linear）埋め込み**: 学習可能なフーリエ周波数で数値を sin/cos 展開してから線形変換。生のスカラーをMLPに入れるより滑らかな傾向を遥かに効率よく表現できる。
- **`Embedding[厳密な値] + PLR(滑らかな値)` という二本立て**: 離散的な暗記と連続的な傾向を足し算で統合し、どちらを使うかを**列ごとにモデルが自動で選べる**。
- **埋め込みだけ weight decay を30倍強くする**: 最も過学習しやすい部分を選択的に正則化。実質的に target encoding の平滑化と同じ効果を勾配降下で実現している。
- **入れ子CVによる fold安全な target encoding**: 学習データをさらに5分割し、各行を含まないデータから encoding を計算。ここを怠るとCVだけ跳ね上がってLBで惨敗する。
- **提出前の健全性チェックセル**: 行数・id の順序込み完全一致・NaN の有無を機械的に検証。そのままコピーして常設する価値がある。

### 評価指標の要約

**ROC-AUC**。予測値の**順位のみ**を見るため、クラス不均衡に強く、閾値を決める必要がない。AUCは微分不可能なので学習は BCEWithLogitsLoss で行い、**モデル選択とブレンド重み探索はAUCで行う**という「代理損失で学習・本番指標で選択」の定石を踏んでいる。ブレンドを `rankdata(v)/len(v)` で順位正規化してから行うのも、指標が順位しか見ないことと完全に整合的。

### 改善点の考察

**他notebookとの比較**: LB上位は [0.97113](https://www.kaggle.com/code/najiama/s6e8-addiction-lb-0-97113)、[0.97099](https://www.kaggle.com/code/daniilkrasnovvv/s6e8-top-1-public-0-97099)、[0.97098](https://www.kaggle.com/code/nikita7364777/s6e8-rank-blend-65-35) と並ぶが、**いずれも公開submissionのrank blend**である。つまり単独手法としてはこの0.97041がほぼ天井付近にあり、上位との差はブレンドの有無でほぼ説明できる。逆に言えば、**このモデルを他の独立な手法と混ぜれば素直に上位に届く**可能性が高い。

**関連文献**: PLR埋め込みの出典は [Gorishniy et al., "On Embeddings for Numerical Features in Tabular Deep Learning" (arXiv 2203.05556)](https://arxiv.org/pdf/2203.05556)。数値特徴の埋め込み方が表形式DLの性能を大きく左右することを体系的に示した論文で、この notebook の設計の理論的裏付けになっている。また [Universal Embeddings of Tabular Data (arXiv 2507.05904)](https://arxiv.org/pdf/2507.05904) は、型別に分けずに数値・カテゴリを統一的に埋め込むアプローチを提案しており、この notebook の「数値を語彙として扱う」発想と近い方向性。

**改善提案**:

1. **他の独立手法とのブレンド**。上位陣との差はほぼこれ。相関の低いモデル（例: FT-Transformer、TabM、あるいは単純なkNN系）を1本足すだけで0.9705超えは狙えそう。原著者自身がOOFで重み探索する仕組みを既に持っているので、追加コストは小さい。
2. **埋め込みの weight decay をハイパラ探索する**。現在 `3e-4` は手で決めた値。これは実質的に平滑化の強さなので、**最も効くつまみの1つ**のはず。値ごとの出現回数に応じて可変にする（レアな値ほど強く正則化）のも自然な拡張。
3. **fold数の再検討**。原著者自身が「compositional（log-ratio）座標の効果はfold数に依存する」と注記している。11foldで消えた効果が別のfold数で復活する可能性があり、**fold数を変えて再評価する価値がある**。
4. **「効かなかったこと」の表を信じすぎない**。ノイズフロアsd 0.00005に対し +0.00015 の効果を「ほぼ無し」と切り捨てているが、ブレンド後には効くことがある。単独で効かない特徴量が、多様性としては価値を持つケース。
5. **PLRの周波数数 `k=24` の調整**。周波数が少ないと滑らかな傾向を表現しきれず、多いと過学習する。埋め込み次元 `d=128` との比率も含めて、まだ探索されていないつまみ。

## 3. RSNA Knee Abnormality Detection

**原著者**: KUNAL DESALE ・ 42 votes ・ Apache 2.0
**リンク**: https://www.kaggle.com/code/kunaldesale2408/rsna-knee-abnormality

⚠️ 789KBの巨大notebookで、base64埋め込みの学習済みパラメータを含む多アームアンサンブル。**モデルそのものより「規律」を学ぶべき** notebook として扱った。

### 学べる主要テクニック

- **多言語ルールベースによる弱教師ラベル生成**: 英・西・仏・蘭・独・トルコ・クロアチア・ギリシャ・ロシア語のレポートから所見を抽出。語幹＋修飾語の**近接マッチング（窓55文字）**で語順の違いを吸収する。`TEAR`（断裂＝異常）と`DEGEN`（変性＝加齢変化）を医学的に区別している点が重要。
- **左右の向き揃え（たった4行で大きく効く）**: 右膝を反転して左膝に揃える。これをしないと「内側」「外側」の学習に必要なデータが実質2倍になる。矢状断だけ反転軸が違う（画像面ではなくスライス軸）のは、面の定義を理解していないと書けない。
- **物理単位での切り出し（`CROP_MM = 130.0`）**: PixelSpacingを使い、撮影解像度が違う施設でも常に130mm四方を切り出す。
- **スロット設計**: (面 × 脂肪抑制) の固定枠にシリーズを1本ずつ割り当てて可変長を固定長にする。**放射線科の読影手順がそのまま構造になっている**。
- **ターゲットのグループ化**（靭帯/半月板/OA/炎症/骨）: 陽性数の少ないラベルが同グループの多いラベルから表現を借りられる。macro-AUCでは稀ラベルの改善が全体に直結するので指標に直接効く。
- **スロット事前分布の注入**: 「骨折は脂肪抑制の冠状断で見る」というドメイン知識を注意ロジットの初期バイアスとして与え、データが増えれば上書きされる。ベイズ的な事前分布そのもの。
- **Mean-Max プーリング**: 局所的な所見（骨折・靭帯断裂 → max）とびまん性の所見（関節液・滑膜炎 → mean）が混在するため、両方計算して連結しヘッドに選ばせる。
- **重みの指紋照合（fingerprint）**: 固定シードのランダム入力に対する出力を期待値と `tol=0.002` で照合。`strict=False` で一部の層がランダム初期化のまま、といった**静かな失敗**を検出する。
- **fail-closed 設計**: 回復可能なエラーは全ラベル0.5で生き延び、`LabelSourceError`（設計の前提が崩れるエラー）だけは再送出して止める。この使い分けが本質。
- **no-regression ゲート**: 新しいアームを足してターゲット別スコアが悪化したら採用しない。失敗時は親の提出をバイト単位で保持。
- **公式メタデータとの監査**: コンペ提供の `Anatomical_Plane` を正解として、自前のDICOMヘッダ推定を検証する。

### 評価指標の要約

**ラベルごとのROC-AUCのmacro平均**。`Fracture` や `Contusion` は陽性が極端に少ないため、macro平均（ラベルごとに計算してから平均）にすることで**稀な所見も頻出ラベルと同じ重み**で評価され、「稀な所見を無視する」戦略が封じられる。この notebook がターゲットをグループ化して表現を共有させ、スロット事前分布で少データラベルを助けているのは、すべてこの指標特性への直接的な対応。提出前に必ず `rank(pct=True)` を通すのも、AUCが順位しか見ないことと整合的。

### 改善点の考察

**他notebookとの比較**（同コンペのBest Score上位を確認）:

| notebook | スコア | 特徴 |
|---|---|---|
| Bend the Knee to DinoV3 (ensembled) | 0.917 | **DINOv3**（より新しい基盤モデル）を使用 |
| RSNA Knee frontier v48 | 0.917 | 反復的なバージョン改良 |
| RSNA Knee baseline v1 | 0.891 | 360 votes・Gold。最も参照されている基盤notebook |

同スコア帯の `Bend the Knee to DinoV3` が **DINOv3** を採用しているのに対し、こちらは **DINOv2 + RadImageNet**。バックボーンの世代で差をつけられる余地がある。

**関連文献**: [Learning co-plane attention across MRI sequences for diagnosing twelve types of knee abnormalities (Nature Communications, 2024)](https://www.nature.com/articles/s41467-024-51888-4) が決定的に関連する。**まさに12種類の膝異常を複数MRIシーケンスから診断する**研究で、シーケンス間の「co-plane attention」により上級放射線科医と同等の性能を達成している。この notebook のスロット設計は各スロットを独立に符号化してから集約するが、co-plane attentionは**シーケンス（面）をまたいだ対応関係を明示的にモデル化**する点で一歩進んでいる。また [OrthoDiffusion (arXiv 2602.20752)](https://arxiv.org/pdf/2602.20752) は筋骨格MRI向けの拡散ベース基盤モデルを提案しており、事前学習ドメインをさらに近づける方向性を示している。

**改善提案**:

1. **co-plane attention の導入**（最も有望）。現在はスロットごとに特徴を作ってからヘッドで集約しているが、Nature Comms の手法のように**矢状断と冠状断の同一解剖部位を対応付けるattention**を入れる。同じ半月板を2つの面から見た情報を明示的に統合でき、内側/外側の判別に効くはず。
2. **DINOv3 への更新**。同スコア帯の競合が既に採用済み。バックボーン差し替えは比較的低コストで、既存のスロット構造・ヘッド設計をそのまま流用できる。
3. **事前学習ドメインをさらに近づける**。RadImageNetは医用画像全般だが、OrthoDiffusionのような**筋骨格MRI特化**の事前学習を使えば、膝という狭いドメインへの適合がさらに上がる可能性。
4. **スロット事前分布を学習で検証する**。現在 `SLOT_PRIOR_TABLE` は人手で決めた固定表。学習後の注意重みを可視化して、**モデルが実際にどのスロットを見ているか**を事前分布と比較すれば、表の誤りを発見できる。「ACLで軸位断を見ている」等が出たら、それ自体が発見になる。
5. **アンサンブルの整理**。3アーム構成だが、base64埋め込みなどで再現性・可読性が犠牲になっている。**各アームの単独スコアと相関行列を出して寄与を測り**、効いていないアームを落とすほうが、保守性とスコアの両方で得な可能性が高い（S6E8のnotebookが相関を表示していたのと同じ発想）。

## まとめ

今日の3本は分野もモデルも全く違うが、**核心はどれも「モデルの大きさ」ではなかった**。

Biohubは**ILPで構造制約を厳密に書き、vetoを非対称に使う**という制約設計。S6E8は**データ生成過程を実験で突き止めてからモデルを作る**という順序。RSNAは**左右を揃える4行**と、**どのエラーで止まりどのエラーで生き延びるかの線引き**。

特にS6E8のsplit-half相関による証明と、RSNAのfail-closed設計は、Kaggleを離れても通用する考え方。今日はトップスコアのnotebookを意図的に外して2位相当を選んだが、その判断は正しかったと思う——0.0006のスコア差より、「なぜそうしたか」が書いてあるnotebookのほうが遥かに資産になる。
