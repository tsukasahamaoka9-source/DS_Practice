## 1. Biohub - Cell Tracking：モデルを触らず、グラフだけ校正する

**原著者**: PUSHPAK TEJA (praxel) ・ 62 votes（Silver）・ Apache 2.0
**リンク**: https://www.kaggle.com/code/praxel/biohub-0-902-motion-division-calibration
**スコア**: Public 0.901 / ランタイム 15分26秒（GPU T4 x2）

### 学べる主要テクニック

- **「重みは一切変えていない」という主張が本体**。検出器（TemporalUNet3D）もエッジスコアラ（Node-transformer）も
  ILPソルバも既存の公開アセットをそのまま使い、変えたのは**後処理のパラメータ5個だけ**。
  それで0.902に届いた、というのがこのnotebookの全部です。
- **パラメータを環境変数で渡す**（`os.environ["BIOHUB_DET_THRESHOLD"] = "0.9700"` 等）。
  推論スクリプト本体を書き換えずに設定だけをnotebookに残せるので、「どの設定で何点出たか」が記録として残る。
- **Precision側の操作とRecall側の操作をペアで入れる**。閾値0.970と最小トラック長6でPrecisionを守り、
  ギャップ復元（max_gap=2）でRecallを取り戻す。F1は片側だけ改善しても伸びないので、この対称性が効く。
- **`VOXEL_SCALE_UM = (1.625, 0.40625, 0.40625)`** — z方向がxyの4倍粗い異方性ボクセル。
  生のボクセル座標で距離を測るとz方向の移動を1/4に過小評価する。3D生物画像で最も踏みやすい罠。
- **`run_stats.csv` を必ず出す**という運用。実際これのおかげで著者は
  「以前のバージョンで使っていたDeepCenterによるゲートが、**ゼロ件しかチェックしていなかった**
  （全候補が構造上ゲートを素通りしていた）」ことを発見し、その機構を削除しています。
  **統計を出さなければ、効いていない機構を効いていると信じ続けていた。**

### 評価指標の要約

検出ノードとリンクエッジのマッチングに基づく**F1系のトラッキング精度**。ありうるエッジの組み合わせが
爆発的に多く極端なクラス不均衡があるため、Accuracyでは「エッジをほとんど張らない」戦略が勝ってしまう。
F1はPrecisionとRecallの調和平均なので、取りこぼしと誤リンクを同時に罰する。
このnotebookが「閾値0.970＋最小長6でPrecisionを守り、ギャップ復元でRecallを戻す」という
**対称な設計**を取っているのは、F1に対して極めて理にかなっている。

### 改善点の考察

**他notebookとの比較**（同コンペのBest Score上位を確認）:

| notebook | スコア | このnotebookが採用していないもの |
|---|---|---|
| biohub ct mix divaug | 0.969 | 分裂イベント特化のデータ拡張（division augmentation） |
| Biohub Cell Tracking Solution | 0.966 | 大規模なマルチシード/マルチモデルのアンサンブル |
| Biohub Solution | 0.966 | 複数の前処理をブレンドする構成 |
| Biohub M001 ens3 sm6 sim2 | 0.917 | 3モデル×類似度のアンサンブル |

今回のnotebookは0.901で、上位陣とは**約0.068の差**があります。ただし上位陣は例外なく重いアンサンブルで、
こちらは**単一モデル＋決定論的な後処理**という構造の明快さが売りです。
「同じ土俵で比べてはいけない」タイプの差であり、伸びしろは素直に残っています。

**関連文献**:
[Higher-Order Cell Tracking Transformer (HOCT, arXiv 2607.11754)](https://arxiv.org/abs/2607.11754) は
エッジ中心のアーキテクチャで候補リンク同士を3D幾何事前分布の下でattentionさせるもので、
ILP後処理のパラメータ（temporal decay, appearance weight, disappearance weight, division weight, node weight）を
明示的に設計しています。今回のnotebookが環境変数で手動グリッド的に決めている部分と、まさに同じ場所です。
また [Tracking by Weakly-Supervised Learning and Graph Optimization (arXiv 2208.11467)](https://arxiv.org/abs/2208.11467) は、
**ILPの重みを structured SVM で自動チューニングする**手法を提案しており、
「面倒な手動グリッドサーチを不要にする」と明記されています。今回の手法の直接の上位互換になりえます。
さらに [Cell as Point (arXiv 2411.14833)](https://arxiv.org/html/2411.14833v4) は
**Adaptive Event-Guided サンプリング**で「完全な分裂シーケンスに均等に露出させる」学習を提案しており、
分裂の扱いが弱点である今回の手法への処方箋になっています。

**改善提案**:

1. **ILP重みの自動チューニング（structured SVM）**。現在は5つのパラメータを手で決めていますが、
   arXiv 2208.11467 の手法なら検証データから最適な重みを直接学習できます。
   このnotebookの成績が「後処理パラメータで決まっている」以上、ここを自動化するのが最も費用対効果が高い。
2. **det threshold の動画ごと適応化**。現在 0.970 の固定値ですが、動画ごとに細胞密度も画質も違います。
   各動画の検出確率分布の分位点から決めれば、Recallの底上げになるはず。
3. **安全な分裂の半径を、細胞サイズで正規化する**。`4.66 um` / `8.5 um` は絶対値ですが、
   発生が進むと細胞は小さくなります。フレーム時刻に応じて半径をスケールさせるほうが自然。
4. **分裂イベント特化の拡張**（0.969のnotebookが採用）。分裂は稀なので学習データが少ない。
   Cell as Point の Adaptive Event-Guided サンプリングのように、
   分裂シーケンスへの露出を意図的に均等化するのが効きそう。
5. **`run_stats.csv` を「診断」から「制御」に格上げする**。現在は事後のログですが、
   「この動画では修復が異常に多い」といった統計をフィードバックして
   パラメータを動画ごとに調整すれば、固定値の限界を超えられます。

## 2. Playground S6E8：条件付け・アブレーション・そして「今日の順位表は何を測っているのか」

**原著者**: GEORGY MAMARIN (georgymamarin) ・ 46 votes（Silver）・ Version 32 of 33
**リンク**: https://www.kaggle.com/code/georgymamarin/s6e8-why-gaming-hours-helps-but-adds-nothing-new
**スコア**: 提示なし（順位を狙う提出ではなく分析notebook）

### 学べる主要テクニック

- **条件付け（conditioning）で単変量AUCを壊す**。`gaming_hours` は単独ならAUC 0.62。
  ところが `daily_screen_time` と `social_media_hours` を細かいセルに固定して測り直すと、
  12セルの平均で**ちょうど0.500**。つまり追加情報をまったく持っていない。
  単変量AUCが答えているのは「この列しか無かったら」という、誰も知りたくない問いです。
- **その結論を、自分でアブレーションして反証する**。§4でモデルに入れて測ると、実際には少し上がる。
  markdownには「Conditioning is an argument. The metric is the judge.（条件付けは議論にすぎない、
  判定を下すのは指標だ）」と書かれています。§4bで、**その価値の約46%が欠損補完由来**だったと突き止めます。
- **制約から作る残差特徴量**。`daily − (social + gaming + work)` = 「説明のつかないスクリーンタイム」。
  単なる引き算なのに単独AUCが約0.76で、これは全12特徴量中4位相当。`gaming_hours`（0.62）より遥かに強い。
- **ラベル生成過程の逆算**。元になった公開データセットを見に行くと、`addicted_label` は
  `daily > 8 OR social > 4` という**閾値ルールで機械的に作られていた**（違反ゼロ件）。
  中間帯の約14%（1,025行）は、どの列でも予測できないコイン投げ。
  → **AUCの理論上限が0.98前後だと計算できます。**
- **Hanley-McNeil (1982) の公式でリーダーボードの測定精度を出す**。公開LBはテストの20%（59,260行）でしか
  採点されず、AUC 0.971 での標準誤差は、**上位10チームの隣接スコア差（9つのうち3つは
  小数点以下5桁でちょうど0.00000）より大きい**。上位陣は統計的には同着です。
- **弱いベースライン効果**。同じターゲットエンコーディングを、弱いLightGBMと強いLightGBMの上で試すと、
  弱い方では大きく改善して見え、強い方ではほとんど何も足しません。
  そして**強いベースライン自体が弱いものより +0.0046 の価値**があり、
  これはこのnotebookのどの特徴量エンジニアリングよりも大きい。
  → 「この特徴量で+0.002！」という報告を見たら、まず**ベースラインの強さを疑う**。

### 評価指標の要約

**ROC AUC**。順位のみを見る指標で、予測値の絶対値（キャリブレーション）は一切問われない。
著者は§8でOOFのヒストグラムとキャリブレーション曲線を並べたうえで
「**2つのパネルは別のことを言っており、リーダーボードに関係するのは片方だけ**」と明記しています。
そして§11で、その指標が**59,260行でしか測られていない**という事実から、
上位陣の順位差が測定精度以下であることを導きます。指標の性質から実務的な意思決定まで一直線に繋がる議論です。

### 改善点の考察

このnotebookは「スコアを上げる」ことを目的にしていないので、改善提案の性質が他の2本と違います。
**手法そのものの限界**に対する提案としました（うち1点は著者自身が§13で先に指摘しています）。

**他notebookとの比較**（同コンペのBest Score上位を確認）:

| notebook | スコア | このnotebookが採用していないもの |
|---|---|---|
| S6E8 Addiction LB 0.97113 | 0.97113 | （コード非公開。OOF/提出CSVの共有のみ） |
| S6E8 Diversity Beats Strength | 0.97113 | 多様性を明示的に最大化するメンバー選択 |
| Mix the Meta-Models... | 0.971 | メタモデル層のブレンド |
| S6E8 Rank blend (65/35) | 0.97098 | 2本のシンプルな順位ブレンド |

上位陣は全て0.971前後に密集していますが、**§11の計算によれば、この密集帯の中の差は測定できていません**。
このnotebook自身がその事実を証明しているのが皮肉であり、同時に最大の貢献です。

**関連文献**:
[Conditional feature importance with generative modeling (arXiv 2501.11178)](https://arxiv.org/pdf/2501.11178) と
[Beyond Black-Box Predictions (arXiv 2504.08712)](https://arxiv.org/html/2504.08712) が、
まさにこのnotebookの§3〜§4を理論側から扱っています。要点は
「marginal（周辺）な重要度は他の特徴量を無視し、conditional（条件付き）な重要度は
相関する特徴量が既に持っている情報を差し引いて評価する」というもので、
このnotebookの手作業のセル分割は、その conditional 版の素朴な実装にあたります。
重要なのは同文献が指摘する**アブレーション法の限界**で、
「特徴量間の相関が高いとき、アブレーションは重要度を過小評価しうる」。
今回 §3 と §4 が食い違ったのは、まさにこの現象です。

**改善提案**:

1. **条件付けをセル分割から生成モデルベースに置き換える**（arXiv 2501.11178）。
   現在は daily × social の12セルという粗いグリッドで、§13で著者自身が
   「**組み合わせに対して構造的に盲目**であり、§4cはそれが最も重要な特徴量を見逃した実例」と認めています。
   条件付き分布からリサンプリングする手法なら、この盲点が原理的に消えます。
2. **中間帯（コイン投げ領域）に絞ったモデリング**。§5の発見によれば、閾値の外側はルールで決まり、
   勝負は約14%の中間帯だけ。この領域だけを対象に別モデルを立てるほうが、
   全データで平均的に良いモデルを作るより効率的なはずです。誰もやっていないなら、そこに余地があります。
3. **残差特徴量の一般化**。`daily − 内訳の合計` が効くなら、
   「内訳の各要素が総時間に占める比率」「残差が負になるかどうかのフラグ」なども試す価値があります。
   物理的な制約から作る特徴量は、単なる交互作用より遥かに強い、というのが§4cの教訓。
4. **AUC上限の推定を明示的に数値化する**。§5で「中間帯14%がランダム」と分かっているので、
   ベイズ最適AUCを計算できます。現在の0.971が上限0.98に対してどこにいるかを出せば、
   「あと何を頑張る価値があるか」の判断が定量的になります。
5. **§11の議論を提出選択のルールに落とす**。「公開LBの差が測定精度以下」と分かった以上、
   最終提出はCVで選ぶべき、という結論を明示的な手順に落とし込むと、notebookの実用価値がさらに上がります。

## 3. RSNA Knee Abnormality Detection：性格の違う「目」を、順位で混ぜる

**原著者**: TONY LI (tonylica) ・ 77 votes（Silver）・ Apache 2.0
**リンク**: https://www.kaggle.com/code/tonylica/rsna-knee-dino-radimagenet-rank-ensemble
**スコア**: Public 0.920（現在の最高スコア帯）/ ランタイム 1分43秒

### 学べる主要テクニック

- **事前学習ドメインで多様性を作る**。35チェックポイントの内訳は、
  DINOv2-small 20本＋DINOv3-small 5本（＝**自然画像**で自己教師あり学習）と、
  RadImageNet ResNet-50 ベースのヘッド10本（＝**医用画像**で教師あり学習）。
  同種モデルのシード違いを増やすより、**間違え方の違うモデルを1本足す**ほうが効く、という発想。
- **確率ではなく順位（rank）で混ぜる**。`_rad_rank_columns()` で**ラベル列ごとに**順位化してから合成。
  AUCは順位しか見ないのだから、混ぜるのも順位で、というのが理屈に合っています。
  確率平均だと、予測の分散が大きいモデルが実質的に大きな票を持ってしまう。
- **ラベルごとにプーリングを変える**（`TTA_TARGET_POOL`）。`Fracture`・`Contusion` は `max`、
  `ACL`・`MCL` は `top2`、`Synovitis` は平均。骨折や骨挫傷は1枚のスライスにしか写らない局所所見なので
  平均すると信号が薄まり、滑膜炎のようなびまん性の所見は平均のほうが安定する。
  **医学的な所見の性質を、プーリング関数の選択に翻訳している。**
- **ラベルごとにアンサンブルの採否を決める**。`_RAD_EXCLUDE = ("Baker's", 'Fracture')` で、
  この2ラベルだけRadImageNetを混ぜていません。「アンサンブルは全ラベル一律に効くとは限らない」。
- **エンコーダ共有＋ヘッド差し替え**。重いResNet-50を1回だけ走らせ、軽いattentionヘッド10個を差し替える。
  計算量が1/10で済む代わりに、**多様性はヘッドの違いからしか来ません**。
  著者はそれを分かっていて、markdownに「E13ヘッドの再利用は、5個の追加チェックポイントではなく
  **2つ目の予測ビューを足しただけ**」と正直に書いています。
- **`fingerprint()` / `check_fingerprint()`** — 固定入力を通して出力ハッシュを照合し、
  重みの読み込み失敗を検出する。35個も扱うとエラーなく静かにスコアが落ちるので、自動検証は必須。

### 評価指標の要約

12ラベル（ACL、MCL、半月板、変形性関節症3種、関節液貯留、滑膜炎、ベーカー嚢腫、骨挫傷、骨折）の
**ROC AUCの単純平均**。所見ごとに有病率が大きく違い `Fracture` などは数%しかないため、
Accuracyでは「全部無し」で95%を超えてしまう。AUCは順位のみを見るので不均衡に強く、
単純平均のため**稀なラベルを捨てる戦略が取れません**。
このnotebookが順位平均・ラベル別プーリング・ラベル別の混合可否と、
すべて「ラベル単位」で設計されているのは、この指標の構造に真っ直ぐ対応しています。

### 改善点の考察

**他notebookとの比較**（同コンペのBest Score上位を確認）:

| notebook | スコア | このnotebookが採用していないもの |
|---|---|---|
| Bend the Knee to DinoV3 (ensembled) | 0.920 | （本notebookのフォーク元。ほぼ同等） |
| RSNA Knee Abnormality | 0.920 | 別系統のスロット設計 |
| RSNA Knee frontier v48 | 0.917 | フロンティア系の段階的追加 |
| RSNA Knee baseline v1 | 0.891 | （371 votes。最も広く読まれている基準実装） |

今回は0.920で**現在の最高スコア帯と同着**です。つまり「上位に追いつく」ではなく
「ここから先どう抜けるか」を考える段階にあります。上位が0.917〜0.920に密集していることは、
Playground枠の§11と同じ問題（**その差は測定できているのか**）を示唆しています。

**関連文献**:
[RadImageNet の原論文（Radiology: AI）](https://pubs.rsna.org/doi/10.1148/ryai.210315) によれば、
まさにこの膝MRIタスクで RadImageNet は ACL断裂 AUC 0.97±0.03、半月板断裂 0.96±0.02 を達成し、
ImageNet（それぞれ 0.91±0.08、0.92±0.06）に対して **4.8% / 4.5% の差**をつけています。
今回のnotebookが RadImageNet ブランチに `_RAD_ALPHA = 0.5` という**半分もの重み**を与えているのは、
この既知の優位性と整合的です。
一方 [2026年の再検証研究](https://www.sciencedirect.com/science/article/pii/S0167865526000255) は
「膝では RadImageNet が最高性能だったが、ImageNet との差は比較可能な範囲だった」と、より控えめな結論です。
また [ModAn-MulSupCon (arXiv 2508.18613)](https://arxiv.org/html/2508.18613) は
**モダリティと解剖部位を意識したマルチラベル教師ありコントラスト事前学習**を提案し、
RadImageNetのサブセットで事前学習したResNet-18でACL断裂分類に良好な結果を出しています。

**改善提案**:

1. **事前学習の「第3の性格」を足す**。現在は自然画像系（DINO）と医用画像系（RadImageNet）の2軸。
   ModAn-MulSupCon のような**マルチラベル教師ありコントラスト事前学習**は、
   「複数の所見が同時に存在する」という本タスクの構造を事前学習の段階で織り込むので、
   既存2軸のどちらとも違う誤り方をする可能性が高い。多様性の源として最も期待できます。
2. **`_RAD_EXCLUDE` の2ラベルを、除外ではなくラベル別の重みに変える**。
   現在は `Baker's` と `Fracture` を二値的に除外していますが、
   ラベルごとに `alpha` を最適化すれば「0か0.5か」より滑らかな解が得られます。
   ただし12個のalphaをCVで最適化すると過学習するので、正則化（全体の平均に引き寄せる）が必要。
3. **エンコーダ共有の代償を測る**。ヘッド10個は同じResNet-50特徴を見ているので相関が高いはずです。
   ヘッド間のOOF予測の相関行列を出せば、「実質何個ぶんの多様性があるか」が分かります。
   その数字次第では、ヘッドを増やすより**2つ目のエンコーダ**を入れるほうが効くと判断できます。
4. **ラベル別プーリングをCVで選ぶ手続きに変える**。現在の `max` / `top2` / `mean` の割り当ては
   ドメイン知識に基づく良い設計ですが、手で決められています。
   ラベル×プーリングの組をOOFで総当たりし、no-regressionゲートで採否を決めれば再現可能な手続きになります。
5. **上位陣との差が測定可能かを先に確認する**。0.917 と 0.920 の差が
   公開LBの標準誤差より小さいなら、そのチューニングは測定できない量を追いかけています。
   Playground枠で学んだ Hanley-McNeil の計算をこのコンペにも適用し、
   **「どれくらいの改善なら信じてよいか」の下限**を先に決めるのが、最も費用対効果の高い次の一手です。

## 今日のまとめ

3本を貫いていたのは **「その差は、測定できているのか」** という問いでした。

- Biohubは、後処理パラメータ5個の校正で0.902を出し、
  **診断ログを出さなければ、効いていない機構を効いていると信じ続けていた**ことを自ら暴きました。
- Playgroundは、単変量AUC・アブレーション・リーダーボードという3つのものさしを順番に疑い、
  最後に **公開LB上位10チームの順位差が統計的に区別できない**ことを示しました。
- RSNAは、ラベルごとに指標の構造へ対応した設計で最高スコア帯に到達し、
  そこから先は**上位との差が測定精度以下かもしれない**という同じ壁の前に立っています。

Kaggleは「+0.001」の世界に見えますが、その0.001がノイズより大きいかを確かめる作業は、
モデルを1つ増やすより遥かに安く、遥かに効きます。今日の3本はどれも、その計算を先にやっていました。
