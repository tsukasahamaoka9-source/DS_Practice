## 1. Biohub - Cell Tracking：小さな改善を、毎回検証して積む

**原著者**: XIAOLEI LIAN (xiaoleilian) ・ 61 votes（Silver）・ Apache 2.0
**リンク**: https://www.kaggle.com/code/xiaoleilian/biohub-m001-ens3-sm6-sim2
**スコア**: Public 0.917 / 作者の内部検証(VAL-24) 0.8623 / ランタイム 17分2秒（T4 x2）

### 学べる主要テクニック

- **前処理そのものを多様性の源にする**。3つの3D U-Netのうち2つは tophat 変換あり、1つはなし。
  同じモデルのシード違いを増やすより、**間違え方の違うモデル**を混ぜるほうが効く。
- **ロジット平均型TTA**。4方向フリップの結果を、`sigmoid` を**かける前の**ロジット段階で平均する。
  `mean(sigmoid(x)) ≠ sigmoid(mean(x))` であり、確率で平均すると自信過剰な予測が平均を支配してしまう。
- **2段階ゲートのハンガリー法**。厳しいゲート(6µm)で確実なペアを先に確定 → 余りだけ緩いゲート(10µm)で救済。
  自信のあるペアを先に固定して、遠くの怪しいペアの横取りを防ぐ。
- **見た目の類似度をリンクコストに足す**（`sim2`）。`cost += 2.0 * |logit(score_prev) - logit(score_curr)|`。
  検出スコアが急変する組み合わせにペナルティをかけ、別細胞への乗り移りを抑える。
- **「1対1の限界」を後処理で埋める（safe divisions）**。ハンガリー法は必ず1対1なので、
  **分裂の2人目の娘は原理的に絶対リンクされない**（実測で分裂 TP/FP/FN = 0/0/14 = 1個も検出できていない）。
  姉妹細胞の**相互最近傍**性と、**分裂後に離れていく**こと（`d(succ(c1),succ(q)) - d(c1,q) ≥ 2.25µm`）で救済する。
  未来の情報を使って「たまたま近い2細胞」と「今まさに分かれた姉妹」を区別する発想が秀逸。

### 評価指標の要約

公式 `tracking_cellmot` 系スコア。ノード検出精度＋エッジ（リンク）のJaccard＋分裂イベントの正誤の複合指標で、
つなぎ忘れ(FN)も余計なリンク(FP)も両方減点される。**時間方向に一貫した軌跡と、分裂という構造変化**を
測ることが目的なので、フレーム単位の検出精度だけを測る指標（mAP等）では代替できない。

### 改善点の考察

| Biohub Cell Tracking Solution | 0.966 | 同上 + 大規模アンサンブル |
| Dark-AGI-Biohub Cell Tracking Solution | 0.952 | 同上 |
| **Biohub M001 ens3 sm6 sim2（本notebook）** | **0.917** | — |
| Biohub - Track Your Cells Development | 0.916 | 別系統のリンク設計 |

**注意すべき文脈**: 0.95以上の上位群は、このVaultで2026-08-04に確認した通り
**「メトリックハック」（提出座標のボリューム範囲外・負の時刻を弾いていない指標実装の脆弱性を突く）**を
含むものが大半です。本notebookの0.917は**正攻法だけで到達した値**であり、
0.969と単純比較すべきではありません。学習対象としてはむしろこちらのほうが健全です。

**関連文献**
- [Cell Tracking according to Biological Needs — Strong Mitosis-aware Multi-Hypothesis Tracker with Aleatoric Uncertainty (arXiv 2403.15011)](https://arxiv.org/pdf/2403.15011):
  1対1割当の代わりに**複数仮説を保持し、不確実性を明示的にモデル化**して分裂を扱う方向。
  本notebookが「PATCH 1」として後付けしている分裂復元を、**追跡アルゴリズムの中に最初から組み込む**設計に相当する。
- [Segment Anything for Cell Tracking (arXiv 2509.09943)](https://arxiv.org/pdf/2509.09943):
  SAM系の基盤モデルを細胞追跡に転用する流れ。専用U-Netの学習なしに検出品質を底上げできる可能性。

**改善提案**

1. **`sim2` の重み(2.0)とゲート(6/10µm)を検証データでグリッドサーチする**。
   作者は +0.0016〜0.0022 の改善を報告しているが、値は手動決め打ち。同じコストの中で最も伸びしろが大きい。
2. **3ブランチを等重み平均ではなく `val_recall` で加重する**。
   2026-08-04レビューでも同じ提案をしたが、本notebookでも等重み（`[1.0]` × 3）のまま。
   モデル間の実力差が無視されている。
3. **safe divisions の FP 31件を減らす**。現状 TP 6 / FP 31 で、精度は約16%。
   「分裂直後に離れる」以外に、**分裂前に親細胞が丸くなる（輝度分布が変わる）**などの
   形態的な手がかりを条件に足せば、FPを削れる可能性がある。
4. **多仮説トラッカー（MHT）への置き換えを検討する**。上記文献の通り、1対1割当＋後処理パッチという構成は
   構造的な上限があり、パッチを増やすほど閾値の手動調整が積み上がる。
5. **Zスケール(1.625µm)を活かした異方性カーネル**。現在は tophat のサイズが `(1,7,7)` でZ方向は1、
   つまりZ方向の背景除去をしていない。Zの実寸を考慮した3D構造要素を試す価値がある。

## 2. Playground S6E8：「0.97115 > 0.97110」は、モデルの話ではなくサンプルの話

**原著者**: RAYK KRETZSCHMAR (raykkretzschmar) ・ 56 votes（Silver）・ Apache 2.0
**リンク**: https://www.kaggle.com/code/raykkretzschmar/why-every-s6e8-notebook-above-0-97110-overfits
**スコア**: Public 0.97115（現在の最上位帯）/ ランタイム 1分7秒

> **選定理由**: このVaultではS6E8を既に16本扱っており、大半が「アンサンブルでLBを0.0000X上げる」内容でした。
> 17本目に同じことをするより、**その上げ幅に意味があるのかを実データで検証したnotebook**を選びました。

### 学べる主要テクニック

- **疑似公開LBシミュレーション**。OOFから**実際の公開LBと同じ59,260行**を層化抽出して「偽の公開LB」を作り、
  そこで最良の重みを選び、**選択に使わなかった行**で評価する。これを10回繰り返す。
  結果は「選んだ場所では上がるが、選ばなかった場所では下がる」——**勝者の呪い**の実演。
- **符号の逆転を証拠にする**。正直なOOFは「生徒モデルを+12%足せ」、公開LBは「-8%引け」と言う。
  値のズレではなく**最適な方向が反転する**ことが、公開行に固有のノイズを拾っている強い証拠になる。
- **実績によるbacktest**。完了済みSeason 6の7エピソードで、公開top10がprivate top10に何チーム残ったかを集計。
  **3回は生存者ゼロ**、S6E7では**公開1位がprivate 440位**。
- **決定論的タイブレーク付きランク化**（`strict_rank` + `np.lexsort`）。同点の並べ方で5桁目のAUCは動くため、
  測定したいものより測定誤差が大きい状況では**まず測定器を固定する**。
- **提出IDを明記した監査可能な記録**。「記憶では上がった」ではなく `submission_ref: 55584395` と書く姿勢。

### 評価指標の要約

**ROC-AUC**（順位のみで決まる2値分類指標）。公開LBは全296,302行のうち約20%（≈59,260行）だけで計算される。
AUC 0.97付近では**5桁目の差は数十ペアの順序が入れ替わっただけ**で生じるため、
`0.97115 > 0.97110` は「モデルが良い」ではなく「**59,260行というサンプルでたまたまそうなった**」の可能性が高い。
著者はこれを推測ではなく実測で示している。

### 改善点の考察

**他notebookとの比較**（Codeタブ上位、いずれも0.971台）

| notebook | スコア | 特徴 |
|---|---|---|
| S6E8: Elite Rank Average Ensemble | 0.97117 | ランク平均（2026-08-10にレビュー済み） |
| S6E8 Addiction Blend LB 0.97117 | 0.97117 | ブレンド |
| **本notebook** | **0.97115** | 上記2つと**区別不能な差**であることを自ら証明 |
| S6E8 Addiction LB 0.97113 | 0.97113 | Najiのteacher（本notebookのベース） |
| S6E8 Diversity Beats Strength | 0.97113 | 多様性重視（2026-08-17にレビュー済み） |

上位5本が**0.00004の幅に収まっている**という事実そのものが、本notebookの主張の裏づけになっています。

**関連文献**
- [The Ladder: A Reliable Leaderboard for Machine Learning Competitions (Blum & Hardt, ICML 2015)](https://proceedings.mlr.press/v37/blum15.pdf):
  この問題への**理論的な処方箋**。提出スコアを「前回より統計的に有意に良いときだけ更新する」という
  Ladderメカニズムを使えば、参加者が何回submitしても公開LBの過学習が抑えられることを証明している。
  本notebookが実測で示した現象の、理論側の対応物。
- [A Meta-Analysis of Overfitting in Machine Learning (Roelofs et al., NeurIPS 2019)](https://papers.nips.cc/paper/9117-a-meta-analysis-of-overfitting-in-machine-learning.pdf):
  Kaggleコンペ多数を横断し、**ホールドアウトの再利用による過学習は実際には限定的**だったと報告。
  本notebookの主張とは一見逆に見えるが、同論文も**上位の僅差の競争では順位が不安定**である点は認めており、
  「全体は壊れないが先端は壊れる」という本notebookの検証3と整合する。両方読むと立場が立体的になる。

**改善提案**

1. **候補数を現実的な規模に増やして再実験する**。著者自身が「11候補・1信号は意図的に甘い設定」と認めている。
   候補を100〜1000に増やしたときの過学習量を測れば、実際のリスクの大きさを定量化できる。
2. **Ladderメカニズムを自分の提出履歴に適用してみる**。手元の提出ログに対して
   「有意な改善のときだけ更新」を適用し、**自分がいつから公開LBを追いかけ始めたか**を可視化する。
3. **private選択の意思決定ルールを事前に文書化する**。「OOFで最良の2本を選ぶ」等を submit 前に決めておけば、
   公開LBを見た後の判断バイアスが入らない。
4. **信号の頑健性を、独立した複数のOOFスキームで確認する**（著者が「考えを変える条件」として挙げているもの）。
   fold数・シード・層化のやり方を変えた3種類のCVで同じ方向が出るかを見る。
5. **ラベル生成過程（合成データ）の仮定を検証する**。Playgroundは合成データなので、
   公開/privateの分割が本当にランダムか（敵対的検証で判別できないか）を確認する価値がある。

## 3. RSNA Knee Abnormality Detection：3系統を「順位」で合流させ、新案は「挑戦者」として審査する

**原著者**: ROMAN TAMRAZOV (romantamrazov) ・ 57 votes（Bronze）・ Apache 2.0
**リンク**: https://www.kaggle.com/code/romantamrazov/rsna-knee-dinosaur-v3
**スコア**: Best 0.921 V18（現在の最上位帯）/ ランタイム 21分57秒（T4 x2）/ コード約18万文字・関数108個

### 学べる主要テクニック

- **事前学習ドメインで多様性を作る**。DINOv2（自然画像・自己教師あり）と RadImageNet ResNet-50（医用画像・教師あり）を併用。
  シード違いを増やすより、**学んだ世界そのものが違うモデル**を1本足すほうが利得が大きい。
- **スロット設計＋代用禁止**。矢状断/冠状断/軸位断 × 脂肪抑制あり/なしの「枠」を先に決め、
  埋まらなければ**空のままにする**。似た別シーケンスで代用すると、モデルが未知の組み合わせを見ることになる。
- **物理サイズ基準のクロップ（130mm）と、幾何情報からの左右復元**。
  内側/外側を区別するラベルは、左右を間違えると**そのラベルだけスコアが反転して崩壊する**。
- **ラベル別アテンションプーリング（`LabelAttentionPool`）**。40枚中2枚にしか写らない骨折の信号は、
  単純平均では消える。**ラベルごとに見るべきスライスを学習**することで、稀ラベルの感度が上がる。
  マクロ平均AUCは稀ラベルも対等に扱うため、ここがスコアに直結する。
- **ラベル別の重みで順位合成**。`v12_weight` は12次元ベクトル。マクロ平均AUCがラベルごとに独立である以上、
  混ぜ方もラベルごとに独立にするのが構造に合っている。
- **★ 採用ゲート（本notebookの核心）**。新しいメタ層(v10→v11→v12)は自動採用されず、
  `_v10_bootstrap_positive_fraction`（280回リサンプルして改善が正の割合）と
  `_v11_fold_consistency`（fold間で一貫して改善しているか）を通過して初めて重みを得る。
- **SHA-256によるアセット検証・指紋照合・フェイルクローズドな提出検証**。
  長時間ジョブで最も怖いのは「静かに間違える」こと。

### 評価指標の要約

**12ラベルAUCのマクロ平均**。有病率が極端に違う（変形性関節症は多く骨折は稀）ため、
マイクロ平均では稀ラベルの改善が報われない。**マクロ平均は12ラベルを対等に扱う**ので、
骨折のような稀だが臨床的に重い所見の改善がそのまま点になる。順位ベースなので、
施設ごとの撮像プロトコル差でスケールがずれていても順序さえ保たれれば減点されない。

**関連文献**
- [A multimodal vision foundation model for generalizable knee pathology (arXiv 2601.18250)](https://arxiv.org/abs/2601.18250):

   focal loss や陽性重み付け、あるいは上記 HiMatch-AD のような training-free 検出の併用を検討する余地がある。
4. **採用ゲートの閾値自体を検証する**。`repeats=280` のブートストラップや fold一貫性の判定基準が
   どれだけ厳しいかは示されていない。**ゲートを厳しくした場合／緩めた場合のスコア差**を測れば、
   このnotebookの一番の武器を定量化できる。
5. **コードの複雑さそのものがリスク**。関数108個・18万文字で、v10/v11/v12 の3世代が同居している。
   `RULES_LEGACY` のような互換パスも残っており、**設定ドリフト**の温床になる。
   採用されなかった経路を削るだけで、再現性と保守性は大きく上がる。

## 今日のまとめ

3本を並べて読むと、**「改善の主張には審査が要る」**という同じ話を、3つの違う言葉で聞くことになりました。

- Biohubは **`0.8547 → 0.8584 → 0.8601 → 0.8623` と刻んだ履歴を公開する**という形で。
- Playgroundは **「その刻みは、あなたが測っている場所でしか起きていないのでは」**という反証の形で。
- RSNAは **ブートストラップとfold一貫性を通った案だけが重みを得る**という実装の形で。

特にPlaygroundの検証2（疑似公開LBシミュレーション）は、手元のどのコンペにもそのまま移植できます。
OOFさえあれば、「自分がLBで選んだ改善が、選んでいないデータでも効くか」を今日から測れます。

そしてBiohubのsafe divisionsが教えるのは別の角度の話で、
**スコアが伸びない原因がモデルではなくアルゴリズムの構造にある**ことがある、ということでした。
ハンガリー法が1対1である限り、分裂は原理的に検出できない。
モデルをもう1本足す前に、**今のパイプラインが構造的に表現できないものは何か**を問う価値があります。
