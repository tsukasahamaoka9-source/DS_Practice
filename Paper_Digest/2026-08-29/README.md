# 2026-08-29 Paper Digest

## Loss Design and Architecture Selection for Long-Tailed Multi-Label Chest X-Ray Classification

- **著者**: Nikhileswara Rao Sulake（Rajiv Gandhi University of Knowledge Technologies, Nuzvid, India）
- **発表**: arXiv preprint, 2026年3月2日（v1）
- **分野**: 医用画像・マルチラベル分類・クラス不均衡（long-tailed learning）
- **リンク**: https://arxiv.org/abs/2603.02294 （HTML版: https://arxiv.org/html/2603.02294v1 ）
- **コード**: https://github.com/Nikhil-Rao20/Long_Tail
- **選定理由**: 直近のKaggle日次レビューで扱っている **RSNA Knee Abnormality Detection**（12所見の
  macro-averaged AUC／稀な所見＝骨折・ベーカー嚢腫がボトルネック）と、問題構造がほぼ一対一で対応する。
  2026-08-28のレビューで挙げた改善案「**稀な所見に的を絞る**」に対して、
  *どの損失関数・どのアーキテクチャ・どの後処理が実際に効いたか* を系統的な実験表で答えている論文だから。

---

## 1. 背景・課題

胸部X線（CXR）のデータセットでは、所見の出現頻度が極端に偏る。心拡大や胸水は頻出する一方、
気胸や肺気腫は稀にしか現れない。この **ロングテール分布** のもとで通常の BCE（二値クロスエントロピー）で
学習すると、勾配の大半を頻出クラスが占めるため、モデルは head クラス（多数派）に強く偏り、
**臨床的には重要だが稀な所見をほとんど検出できなくなる**。

さらに CXR は本質的に **マルチラベル**（1枚に複数所見が同時に存在しうる）であり、
単一ラベルのロングテール研究の知見がそのままは移植できない。

問題はここからで、著者の指摘によれば **これまでの研究は「損失関数」「バックボーン」「後処理」を
個別にしか評価していない**。実務者としては「結局どの組み合わせを選べばいいのか」が分からない。
本論文はその空白を埋めることを目的に、CXR-LT 2026 ベンチマーク（PadChest 由来、
約143K枚 × 30ラベル）で、これら3軸を **同一条件で総当たり的に比較** している。

## 2. 提案手法の概要

新手法の提案ではなく、**既存手法の系統的な組み合わせ評価（アブレーション）** が本体。
比較した3軸は以下。

### 2.1 損失関数（3種）

| 損失 | 考え方 |
|---|---|
| **BCE** | ベースライン。全クラス・全サンプルを等価に扱う。 |
| **Asymmetric Loss (ASL)** | マルチラベル用。正例と負例で focusing パラメータ（γ₊, γ₋）を変え、**簡単な負例の勾配を潰す**。 |
| **LDAM + DRW** | 本命。下記。 |

**LDAM（Label-Distribution-Aware Margin）** は、クラス *j* の決定境界に
`Δⱼ = C / nⱼ^(1/4)`（nⱼ はそのクラスのサンプル数）というマージンを課す損失。
サンプル数が少ないクラスほどマージンが大きくなる = **「稀なクラスは、より余裕をもって正しく分類しろ」**
と要求する。ロジット zᵧ から Δᵧ を引いた上で softmax/BCE を取るので、
稀なクラスは「ギリギリ正解」では損失が減らない。

**DRW（Deferred Re-Weighting）** は、この LDAM に段階的な再重み付けを組み合わせる運用。
学習の最初は **一様重み** で回し、全エポックの60%を過ぎてから **クラス頻度の逆数による重み** に切り替える。
狙いは「まず汎用的な特徴表現を素直に学ばせ、それができてから初めて tail クラスに集中させる」こと。
最初から再重み付けすると、少数サンプルに過剰適合した歪んだ特徴を学んでしまう。

> なお本論文では、LDAM は本来 single-label softmax 用の定式化なので、
> **30クラスそれぞれを独立した二値分類とみなし、クラスごとの LDAM マージンを BCE の枠組みの中に入れる**
> という形でマルチラベルに移植している。ここは論文独自の適応であり、原論文そのままではない。

### 2.2 アーキテクチャ（7種）

ResNet-50 (25M) / ResNet-101 (44M) / DenseNet-121 (8M) / DenseNet-169 (14M) /
EfficientFormerV2-S (22M) / ConvNeXt-Base (89M) / ConvNeXt-Large (198M)。
すべて ImageNet 事前学習済み、ヘッドは GAP → LayerNorm → Dropout → Linear(30)。

### 2.3 後処理（3種）

- **cRT（classifier Re-Training / 分類器の再学習）**: 2段階学習。
  第1段でネットワーク全体を LDAM-DRW で end-to-end 学習 → 第2段で**バックボーンを凍結し、
  分類器ヘッドだけを初期化し直して、クラス均衡サンプリングで再学習**する。
  「表現学習」と「分類器の最適化」を分離するのが狙い（Kang et al., ICLR 2020 の decoupling）。
- **TTA**: 水平反転 + ±5°の微小回転の平均。
- **アンサンブル**: 検証性能に応じた重み付き平均。

### 2.4 実験条件

512×512、AdamW（lr=1e-4, wd=1e-5）、cosine annealing、50エポック、FP16。
**バッチサイズ8**（単一の RTX 4050 / VRAM 6GB という制約による）。
分割は **患者単位の GroupShuffleSplit で 90/10**（患者リークを防ぐ）。

## 3. 主な結果

### 3.1 損失関数の効果が支配的

ResNet-50 固定で、BCE → LDAM+DRW にするだけで **mAP 0.3248 → 0.4241（相対 +30%）**。

一方 **Asymmetric Loss は 0.0667 mAP と壊滅的に失敗している**。
著者の解釈は「CXR-LT の不均衡が極端すぎるため、デフォルトの (γ₊=0, γ₋=4) が
**ただでさえ疎な正例の勾配まで過剰に抑制**し、モデルがほぼ全クラスで確率ゼロ近傍を出すようになった」。
**ASL は万能ではなく、不均衡の度合いに応じて γ を調整しないと逆効果になる** という重要な警告。

### 3.2 アーキテクチャ：ConvNeXt が明確に強い

主要な行を抜粋（開発セット、すべて LDAM+DRW）:

| Model | Post-training | AP (mAP) | AUC | F1 | ECE |
|---|---|---|---|---|---|
| ResNet-50 | BCE（参考） | 0.3248 | 0.8410 | 0.3222 | 0.8884 |
| ResNet-50 | — | 0.4241 | 0.8435 | 0.2676 | 0.5575 |
| ResNet-50 | cRT | 0.4303 | 0.8828 | 0.3233 | 0.8300 |
| ResNet-50 | cRT + TTA | 0.4325 | 0.8864 | 0.3102 | 0.8247 |
| ResNet-101 | — | 0.4584 | 0.8679 | 0.2564 | 0.5332 |
| DenseNet-121 | — | 0.3967 | 0.8334 | 0.2119 | 0.5422 |
| EfficientFormerV2-S | — | 0.4869 | 0.8818 | 0.3161 | 0.5215 |
| ConvNeXt-Base | cRT + TTA | 0.5217 | 0.8961 | 0.2659 | 0.8909 |
| **ConvNeXt-Large** | **—** | **0.5220** | 0.8832 | **0.3765** | 0.5506 |
| ConvNeXt-Large + EffFormerV2-S | cRT + アンサンブル | 0.4990 | **0.8951** | 0.2556 | 0.7037 |

読み取れること:

- **DenseNet-121 は CXR の定番（CheXNet 以来）だが、ここでは最下位クラス**（0.3967）。
  「この分野の定番だから」という理由でのバックボーン選択は、もはや根拠が弱い。
- **EfficientFormerV2-S は 22M パラメータで 0.4869** と、ResNet-101 (44M) を上回りつつ
  **ECE（キャリブレーション誤差）も最小（0.5215）**。計算予算が限られるなら第一候補。
- **アンサンブルは AUC は上げるが（0.8951）、mAP と F1 では最良の単一モデルに負けている**。
  「混ぜれば良くなる」は成り立っていない。

### 3.3 後処理はランキング指標だけを上げる（＝ここが本論文の一番の学び）

- **cRT は AUC を明確に改善する**（ResNet-50: 0.8435 → 0.8828）。
  少数クラスの決定境界の分離度が上がるため。
- **しかし F1 には一貫して波及せず、ECE はむしろ悪化する**（0.5575 → 0.8300）。
  つまり cRT が改善しているのは **クラスの分離可能性であって、確率の質ではない**。
- **TTA も同様**。AP/AUC は微増するがキャリブレーションを悪化させる。

### 3.4 開発 → テストの落差についての率直な分析

公式テストリーダーボードでは **mAP 0.3950 / AUC 0.8591 / F1 0.0945 で 68チーム中5位**。
開発セットの 0.5220 から **mAP が 0.13 も落ちている**。著者はこれを取り繕わず、原因を3つ挙げている:

1. 内部検証分割への過適合
2. 確率キャリブレーションと閾値選択が不十分
3. アンサンブルの重みを **ランキング指標に寄せて調整しすぎた**（instance-level を犠牲にした）

特に **F1 = 0.0945** は異常に低い。CAM（クラス活性化マップ）を見ると
**病変の位置自体は正しく当てている**のに、確率が閾値の近傍に固まっているため
instance-level では取りこぼしている。**「ランキングは正しいが、しきい値が正しくない」** という状態。

なお1位の CVMAIL x MIHL（arXiv:2602.13430）は mAP 0.5854 / AUC 0.9259 / F1 0.3518 で、
**すべての指標でバランスが取れている**。3位の VIU は mAP 0.4599 と本論文より少し上なだけだが
F1 は 0.4504 と圧倒的に高い。**mAP を追う戦略と F1 を追う戦略は同じではない**ことが表から直接読める。

## 4. Kaggleでの実践への示唆

### 4.1 RSNA Knee（12所見・macro-AUC）への直接の対応

RSNA Knee は「12所見の macro-averaged AUC」で、**骨折とベーカー嚢腫という稀な所見が
頻出する ACL や変形性関節症とまったく同じ重みを持つ**。これは CXR-LT の
「30ラベルの macro-mAP」と**構造的に同一の問題**であり、本論文の結論はほぼそのまま輸入できる。

現在の公開上位帯（DINOsaur 系統、0.936）は、私が2026-08-28に読んだ範囲では
**損失関数は BCE ベース**で、伸ばし方が「4系統のアンサンブル + 所見単位の融合重み」という
**後処理側**に寄っている。本論文が示したのは、**同じアーキテクチャのまま損失を LDAM-DRW に変えるだけで
mAP が相対30%動いた**という事実であり、後処理より上流に手つかずのレバーが残っている可能性が高い。

ただし **重要な留保**がある。RSNA Knee の指標は **AUC** であって mAP ではない。
本論文で cRT が最も明確に改善したのは **まさに AUC** で（+0.04）、逆に苦戦した F1 や ECE は
RSNA では**そもそも評価されない**。つまり RSNA にとっては、
**本論文が「弱点」として報告した部分が、そもそも問題にならない**。
この論文の失敗（F1 0.0945）は RSNA には転移せず、成功（AUC の改善）だけが転移する — という
**指標の違いによる非対称な移植可能性**が、今回いちばん実務的に価値のある観察だと思う。

### 4.2 逆向きの警告

一方で、2026-08-28 のレビューで確認した RSNA notebook（`rsna-base`）は
**ラベルが LLM によるレポート解釈（構造化ラベルは4,407件中58件のみ）** である。
LDAM は「クラス j のサンプル数 nⱼ」を margin の計算に直接使うため、
**nⱼ が LLM の抽出精度に依存している場合、margin そのものが歪む**。
稀な所見ほど LLM の false negative の影響を受けやすく、
**「本当は稀ではないのに、LLM が拾えていないだけで稀に見えるクラス」に過大なマージンを課す**
リスクがある。LDAM を入れるなら、**nⱼ を LLM ラベルから数えるのか、
58件の構造化ラベルの有病率から推定するのか**を先に決めるべき。

### 4.3 Playground 系（S6E8 等）への示唆

S6E8 は単一ラベルの ROC-AUC で不均衡もそこまで極端ではないため、LDAM の出番は薄い。
ただし本論文の **「アンサンブルは AUC を上げたが mAP/F1 では単一モデルに負けた」** という結果は、
S6E8 で観測した「ランクブレンドで上位が 0.9712 に収束し、差が実質ノイズ」という現象と同じ根を持つ。
**アンサンブルはランキングを安定化させるが、新しい情報を生まない**。

## 5. 実装可能な仮説

> RSNA Knee Abnormality Detection（`DS_Projects/` の該当 research/backlog.md に起こす粒度）

### 仮説 1: 12所見それぞれに LDAM マージンを課し、DRW を60%地点で発火させる

- **手法**: 既存の12ヘッド BCE を、クラスごとに `Δⱼ = C / nⱼ^(1/4)` を引く LDAM-BCE に差し替える。
  `nⱼ` は訓練データ内の各所見の陽性件数。学習の 60% 経過時点で、クラス頻度の逆数重みに切り替える（DRW）。
  実装は BCE の直前でロジットから所見ごとの定数を引くだけなので、10〜20行で済む。
- **期待インパクト**: 稀な2所見（骨折・ベーカー嚢腫）の AUC 改善。macro 平均なので、
  この2つが各 +0.02 動けば全体で +0.003 程度。本論文の相対 +30% がそのまま出るとは考えないが、
  **head クラスを犠牲にせず tail だけを押し上げられるか**が検証の主眼。
- **工数**: 小（半日）。損失関数の差し替えのみで、パイプラインの他部分は不変。
- **リスク**: 上記 4.2 の通り、`nⱼ` が LLM ラベル由来だと margin が歪む。
  まず `nⱼ` を LLM ラベル版と、58件の構造化ラベルから外挿した版の2通りで出して比較する。
- **出典**: 本論文 Table 1（ResNet-50: 0.3248 → 0.4241）、
  原論文 Cao et al., NeurIPS 2019 (LDAM)。

### 仮説 2: cRT（バックボーン凍結 + ヘッドのみクラス均衡再学習）を後処理として追加

- **手法**: 既存の学習済みモデルはそのまま使い、**バックボーンを凍結して分類ヘッドだけ初期化し直し、
  クラス均衡サンプリングで数エポック再学習**する。既存の重みを捨てずに済むのが利点。
- **期待インパクト**: 本論文では AUC が ResNet-50 で +0.039、ConvNeXt-Base でも改善。
  **RSNA の指標は AUC そのものなので、この論文で最もクリーンに効いた改善が直撃する**。
  副作用の ECE 悪化と F1 低下は RSNA では評価されない。
- **工数**: 小〜中（1日）。バックボーン再学習が不要なので GPU 時間が安い。
  Code Competition の実行時間制約にも収まる（推論時のコストはゼロ）。
- **リスク**: 本論文でも cRT が F1 に波及しない例が複数あり、
  「分離度は上がるが確率は歪む」。AUC 指標なので問題にならないはずだが、
  4系統アンサンブルの**融合重みを確率ベースで決めている場合、その前提が崩れる**ため、
  cRT 後は融合重みを再最適化する必要がある。
- **出典**: 本論文 Table 1（cRT 行）、Kang et al., ICLR 2020（decoupling representation and classifier）。

### 仮説 3: バックボーンを DenseNet/ResNet 系から ConvNeXt または EfficientFormerV2 に差し替える

- **手法**: 現行の検出・分類バックボーンを ConvNeXt-Base、あるいは効率賞（Efficiency Prize $18,000）を
  狙うなら EfficientFormerV2-S に差し替える。
- **期待インパクト**: 本論文では同じ損失で DenseNet-121 (0.3967) → ConvNeXt-Base (0.4855) と大差。
  特に **EfficientFormerV2-S が 22M で ResNet-101 (44M) を上回りつつ ECE 最小**という点は、
  2026-08-28 のレビューで指摘した「RSNA の効率賞は公開上位が薄く狙い目」という観察と噛み合う。
  **2m55s という実行時間を維持したまま AUC を上げられる可能性**がある。
- **工数**: 中（2〜3日）。再学習が必要で、事前学習重みの入手と入力解像度の調整も要る。
- **リスク**: 本論文は 512×512・バッチサイズ8（VRAM 6GB 制約）という**やや窮屈な条件**での比較であり、
  大バッチ・高解像度で同じ序列になる保証はない。特に ConvNeXt-Large (198M) の優位は
  単に容量が大きいだけかもしれない。**まず EfficientFormerV2-S で費用対効果を確認する**のが順当。
- **出典**: 本論文 Table 1（アーキテクチャ比較行）。

## 6. 未読了・不確かな部分（正直な記載）

- **本文（HTML版）は通読したが、Figure 1（CAM 可視化）の画像そのものは確認していない**。
  「病変の位置は正しく当てているが確率が閾値近傍に固まっている」という記述は著者の主張をそのまま引いている。
- **GitHub のコード（https://github.com/Nikhil-Rao20/Long_Tail ）は未確認**。
  LDAM のマルチラベル適応の実装細部（margin をロジットから引く位置、DRW の重みの正規化方法）は
  論文の記述から推測しており、実装時にはコードを読む必要がある。
- **論文中の参考文献 [14] は EfficientFormerV2 を指しているはずだが、
  引用されているのは Tan & Le の EfficientNetV2 の論文**（別モデル）。
  誤引用と思われるので、EfficientFormerV2 を採用する際は正しい原論文を別途当たること。
- **ECE の値が全体的に 0.5〜0.9 と極端に大きい**。通常 ECE は 0〜1 の範囲だが 0.1 以下が普通で、
  0.88 という値は「ほぼ完全にキャリブレーションが崩壊している」ことを意味する。
  マルチラベルでの ECE 定義（30クラスをどう集約したか）が本文に明記されておらず、
  **この列の値を他論文と比較するのは危険**。
- **1位解法（arXiv:2602.13430）はアブストラクトのみ確認**。
  「imbalance-aware multi-label learning strategy」の中身は未読。
  mAP 0.5854 / F1 0.3518 と両立させている以上、本論文が取りこぼした部分の答えを持っている可能性が高く、
  **次回のダイジェスト候補**として有力。
