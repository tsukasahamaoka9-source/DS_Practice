一方でバックボーン側（DINOv3、OrthoFoundation、co-plane attention）は 2026-08-08 のOrthoDiffusion回と 08-17/08-18 のレビューで既に十分カバーしている。**未着手で、かつ効果の上限が最も高いのがラベル生成側**なので、今回はそこを直撃する論文を選んだ。過去のPaper Digest（08-01 金融ポートフォリオ、08-05 HOCT、08-08 OrthoDiffusion、08-12 Cell-TRACTR）とは重複しない。

### 背景・課題

放射線レポートには「その画像に何が写っているか」という情報が自然言語で豊富に書かれている。これを機械的にラベル化できれば、高価な手動アノテーションなしで画像モデルを学習できる（＝レポート由来の弱教師あり学習）。しかし既存手法には3つの限界がある、と著者らは整理している。

1. **ルールベース（正規表現・辞書）**: 言語的な揺らぎに弱い。同じ「前十字靭帯断裂」でも語順・省略・否定・不確実表現のバリエーションが無限にあり、辞書を書き足し続けることになる。
2. **教師あり学習モデル**: 大量のアノテーション済みデータが必要で、新しいラベル体系（taxonomy）や新しい言語に移すたびに作り直しになる。
3. **最近のLLMベースの手法**: クローズドソース（API課金・データを外部に出せない）か、計算資源を大量に食うモデルに依存しており、臨床現場での運用に向かない。

さらに、既存研究のほとんどが**英語のみ・単一モダリティ・単一のラベル体系**に限定されている。これは実データの現実と合っていない。

### 提案手法の概要

**MOSAIC** は「小さい・多言語・ラベル体系に依存しない」の3点を同時に狙った、レポート分類のアプローチ。

- **ベースモデル**: **MedGemma-4B**（Googleの医療特化Gemma、40億パラメータ）。オープンアクセスで、4bit量子化すれば**24GBのコンシューマ向けGPU（RTX 4090）1枚**でファインチューニングまで完結する。
- **2つの運用モード**:
  - **zero-shot / few-shot プロンプティング**: 学習なしで、プロンプトに所見リストと出力形式を書くだけで分類させる。few-shot（3-shot）は数例を例示として与える。
  - **軽量ファインチューニング**: LoRA系の低コスト学習（Unsloth利用）。少量データで済む。
- **taxonomy-agnostic（ラベル体系非依存）**: 分類したい所見の一覧を**プロンプト側で差し替えるだけ**でタスクが変わる設計。モデルのヘッドを固定クラス数で作り込まないため、「12所見」でも「48所見」でも同じ仕組みで動く。
- **陽性/陰性/不確実の3値**: 単なる「所見の有無」ではなく、`+`（definitely present）・`−`（definitely absent）・`~`（uncertain mention）を区別する。評価も**(+)F1 と (−)F1 を別々に**マクロF1で報告しており、**否定表現の扱いが評価指標に明示的に組み込まれている**。
- **多言語の積み上げ学習**: 英語（MIMIC/PadChest-en）だけの単一言語ベースラインから始め、スペイン語（+S）→ フランス語（+C, CASIA-CXR）→ デンマーク語（+D, DanskCXR）と学習データを段階的に足していき、言語を足すことが他言語の性能を落とすか（干渉するか）を検証している。
- **データ拡張と英訳の検証**: LLMによるレポートのパラフレーズ拡張と、「原文のまま処理する vs 英語に機械翻訳してから処理する」の比較も行っている。

### 主な結果

- **5つの胸部X線データセット（英・西・仏・丁）でマクロF1平均88**。論文は「専門家レベルに近づく、あるいは超える」と表現しており、必要GPUメモリは24GBのみ。
- **多言語の積み上げは干渉しないどころか改善する**: 学習データに言語を足していくと、平均スコアが概ね単調に上がっていく（英語のみ → +西 → +仏 → +丁 で、平均が 80/82/84 → 82/81/84 → 84/87/88 → 88/89/92 という並びで報告されている。3つ組は評価条件の違い）。「多言語化するとどの言語も中途半端になる」という直感は、少なくともこのタスクでは成立しなかった。
- **データ拡張を併用すれば、新しい言語・新しいラベル体系への適応に必要なアノテーションは80件程度で足りる**（論文の主張の中で最も実務インパクトが大きい部分）。
- **小さいモデルが健闘する**: MedGemma-4B は Llama-8B（2倍のサイズ）を上回り、Gemma-12B（3倍のサイズ）とほぼ同等。MedGemma-27B や Llama-70B はさらに強いが、それらは94GBのH100を要し、コンシューマGPUでは動かない。**医療ドメイン事前学習が、パラメータ数の差を埋めている**構図。
- **ファインチューニングは一貫して効く**が、ドメイン外データ（デンマーク語MRI）ではゼロショットからの改善幅がとりわけ大きい。逆に、既に適合しているデータに対して余分な言語を足すと**わずかに劣化する場合もある**と正直に報告されている。
- **英訳を挟むかどうかは条件依存**。翻訳が性能を上げるケースが報告されている一方、常に有利ではない。

### Kaggleでの実践への示唆

**RSNA Knee Abnormality Detection の構造は、この論文の設定とほぼ一対一で対応している。**

| MOSAIC の設定 | RSNA Knee の現状 |
|---|---|
| 多言語レポート（英・西・仏・丁の4言語） | 16施設・十数言語（英・西・仏・蘭・独・土・克・希・露…） |
| taxonomy-agnostic な所見リスト | 12所見（ACL/MCL/内側・外側半月板/OA×3/関節液/滑膜炎/ベーカー嚢腫/骨挫傷/骨折） |
| 陽性 / 陰性 / 不確実 の3値 | 「断裂あり」vs「断裂は認めない」の判別が未検証（08-17指摘） |
| ルールベースは言語的揺らぎに弱い、が出発点 | まさに正規表現＋±55文字の近接マッチングで実装されている |
| 24GBのGPUで完結 | ラベル生成は**オフライン前処理**なので、Code Competitionの推論時間制限とは無関係 |

最後の行が実務上とても重要だ。RSNA Knee はインターネット遮断のCode Competitionだが、**レポートからのラベル生成は学習データに対する前処理であって、提出用notebookの中で走らせる必要がない**。手元（あるいはKaggleの学習用notebook）で一度MOSAIC相当のパイプラインを回して改良版ラベルCSVをDatasetとして固定してしまえば、推論側のコードは一切変えずにラベル品質だけを差し替えられる。**「上流のボトルネックに、下流のコストゼロで手を入れられる」**という、極めて費用対効果の高い改善経路がここにある。

もう一点、評価指標との接続が綺麗に効く。RSNA Knee の指標は**所見ごとのROC-AUCのマクロ平均**なので、`Fracture` や `Contusion` のような陽性が極端に少ない所見の改善が全体スコアに直結する。稀な所見ほど、レポート中の記述パターンが少なく、正規表現辞書のカバレッジが薄いはずで、まさにMOSAICが「ルールベースが取りこぼす部分」として想定している領域と重なる。「80件のアノテーションで新しい言語・体系に適応できる」という主張が正しければ、**弱点言語 × 稀少所見のセルにだけ80〜200件の検証ラベルを作る**という、極めて焦点の絞られた投資が可能になる。

一方で慎重に見るべき点もある。MOSAIC が扱ったのは主に胸部X線と脳MRIで、**膝MRIの整形外科ドメインでの検証はない**。MedGemma の医療事前学習が筋骨格系の語彙（半月板・十字靭帯・軟骨下骨髄浮腫など）をどれだけカバーしているかは未知数で、そこが薄ければ 4B というサイズが逆に足を引っ張る可能性がある。また、論文の評価は「人手アノテーションとの一致（F1）」であり、**「ラベルを改善したら下流の画像モデルのAUCが上がるか」は検証されていない**。ラベルノイズが実は正則化として働いていた、という逆転もあり得るので、必ずno-regressionゲート（08-17/08-18で繰り返し出てきた規律）を通して測ってから採用すべき。

### 実装可能な仮説

> そのまま `DS_Projects/.../research/backlog.md` に起こせる粒度で書く。

**仮説1: MedGemma-4B（4bit量子化）で全レポートを12所見×3値に再ラベリングし、既存の正規表現ラベルとの不一致セットを作る**

- **手法**: 12所見のリストと `{陽性 / 陰性 / 不確実 / 言及なし}` の出力スキーマをプロンプトに埋め、原文言語のままzero-shot/3-shotで全レポートを分類。既存の正規表現ラベルと突き合わせ、不一致した study だけを抽出する。まずはラベルを差し替えず、**不一致率を言語×所見のクロス集計で可視化するだけ**に留める（08-17の改善提案3をこの手段で実行する形）。
- **期待インパクト**: 直接のスコア改善ではなく「どこが壊れているかの地図」。ここで不一致率が数%程度なら、この方向への投資は打ち切ってよい（＝**安価な足切り判定**として機能する）。逆に特定言語で20%超の不一致が出れば、仮説2の投資根拠になる。
- **工数**: 中（オフライン推論。レポート数次第だが、4Bモデル・4bit量子化なら数時間〜1日）。
- **出典**: MOSAIC §Method（taxonomy-agnostic プロンプト設計、24GB GPUでの運用）

**仮説2: 不一致率の高い弱点言語だけに絞って80〜200件の検証ラベルを作り、そこだけ軽量ファインチューニング**

- **手法**: 仮説1で特定した弱点言語（トルコ語・クロアチア語・ギリシャ語あたりが候補）について、80〜200件のレポートに対して所見ラベルを付ける（既存の正規表現とLLMの両方が同じ答えを出したものは正解とみなし、不一致分だけ精査すれば人手コストは大きく圧縮できる）。これをMOSAIC流の少量ファインチューニングに投入し、その言語のラベル品質を上げる。
- **期待インパクト**: 稀少所見（Fracture / Contusion）のラベル品質改善を通じたmacro-AUCの底上げ。マクロ平均なので稀少所見1つの改善がそのまま 1/12 の重みで効く。改善幅は不一致率次第だが、レポート抽出が本当に上流ボトルネックなら、バックボーン差し替え（DINOv2→v3）と同程度かそれ以上のリターンがあり得る。
- **工数**: 中（アノテーション80〜200件＋LoRAファインチューニング1回。2〜3日）。
- **出典**: MOSAIC §Results（"as few as 80 annotated samples"、多言語積み上げ学習の表）

**仮説3: 否定・不確実表現の分離評価を、指標として自前で導入する**

- **手法**: MOSAIC が (+)F1 と (−)F1 を分けて報告しているのに倣い、自前のラベル生成ロジックについても**「陽性を当てる性能」と「否定文を正しく陰性にする性能」を別々に測る**。「前十字靭帯に断裂は認めない」型の否定文を各言語から数十件抜き出した小さな評価セットを作り、現行の正規表現パイプラインを通す。
- **期待インパクト**: スコアへの直接効果はないが、08-17で「検証されていない」と指摘された穴を塞ぐ。ここが壊れていれば偽陽性ラベルが大量に混入していることになり、仮説1・2の優先度が跳ね上がる。**最も工数が小さく、最も早く判断材料が出る**ので、着手順としてはこれが先。
- **工数**: 小（半日〜1日）。
- **出典**: MOSAIC §Evaluation（(+)F1 / (−)F1 の分離報告、3値ラベル体系）
